# Agentic Work Infra

## 项目定位

本项目研究智能工业革命中的一项基础设施问题：

> 当越来越多认知劳动由 Agent 执行，人、Agent 与长期工作资产应如何组织，才能让工作跨会话、跨工具、跨团队持续推进，并在真实结果中不断积累？

这里的重点不是某个模型、Agent App、知识库产品或内容管理系统，而是它们共同依赖的工作基础。项目暂用“Agent 原生工作基础设施”描述这个问题，名称本身也可以被后续证据修正。

## 为什么值得独立研究

模型和 Agent Harness 正在降低执行复杂工作的门槛，但一次任务能够完成，不等于长期工作能够持续。真实工作仍然会遇到目标漂移、上下文丢失、真源混乱、结果无法验收、反馈没有回流等问题。

媒体创作、企业知识库、投标、财务、产品开发和其他行业表面上不同，却可能共享同一条工作主干：人提出意图，Agent 使用上下文完成工作，人判断方向，现实结果验证产出，验证后的经验再进入下一次任务。

这是一项待验证的跨行业假设，不是已经成立的普遍规律。

## 核心问题

项目首先回答五个问题：

1. **意图**：一项长期工作为什么开始，什么变化才算有价值？
2. **上下文**：Agent 应依据哪些信息开展工作，哪些信息有效、存疑或已经失效？
3. **真源**：当前有效判断和产物在哪里，其他对象与它是什么关系？
4. **结果**：怎样证明工作产生了可接受的真实结果，而不只是生成了文件？
5. **积累**：交付、使用和反馈怎样进入下一次工作，使能力持续增长？

## 当前假设

- 真正需要管理的不是孤立“内容”，而是长期工作的连续性。
- 知识库、内容生产、Handoff 和可视化面板可能是同一工作系统在不同任务中的视图，而非简单的上下级关系。
- 同一个物理对象在不同任务中可能承担不同作用，不能仅靠固定文件类型决定处理规则。
- 通用方法只能保留跨领域仍然成立的约束；目录、字段、平台和具体工作流属于领域策略或载体实现。

以上均为候选判断。一个由规则本身造成、可以复现的有效反例，就足以要求收窄或删除对应判断。多个独立领域的成功案例只能提高可信度，不能把经验宣布成不可证伪的真理。

## 验证方式

项目从真实工作倒推方法，不先设计通用平台：

1. 选择相互独立的真实场景，记录工作怎样开始、推进、验收和积累。
2. 找出跨场景重复出现的失败，以及失败究竟来自通用工作缺口、领域知识还是工具能力。
3. 提炼最小候选模型，并主动寻找反例。
4. 把跨领域约束与领域策略分开，再回到真实任务验证。
5. 证据足够后，才决定产物应当是方法论、协议、Skill、可视化工作台，或它们的组合。

首批观察场景包括内容创作、企业知识库和投标/FDE 工作。它们只是起点，不能单独证明方法适用于所有行业。

## 当前不做

- 不把传统 CMS、知识库或项目管理软件直接改名为 Agent 基础设施。
- 不预设最终产品形态，不先做可视化面板。
- 不把某个仓库的目录、文件名、发布流程或业务术语提升为通用规则。
- 不为了完整感创建空模板、状态看板、路线图或尚无证据支撑的对象分类。
