# 企业知识跨任务复用验证

中文 | [English](enterprise-knowledge-reuse.en.md)

## 结论

一次已经完成的真实投标知识复用任务证明：知识写入成功和知识产生业务价值是两个不同结果。只有新的独立任务能够找到实际内容、区分稳定事实与本次项目变量，并把它们用于可检查交付物，才能证明知识复用成功。

这次任务同时提供了一个反例：已经完成并稳定存在的知识可以依靠知识地图、可读组件和新任务输入跨会话复用，不需要为它永久维护当前执行面。因此，当前执行面只适用于尚未完成、方向仍可能变化的工作，不能覆盖所有长期资产。

## 验证边界

- 证据来自本地专业交付项目中已经完成并记录的真实任务；本轮审计已有结果，没有重新运行客户业务。
- 原始企业资料、知识组件、生成标书、账号、平台状态和运行日志继续留在本地项目。
- 公共记录不包含客户身份、原文、业务参数、文件路径或可以还原材料的细节。
- 这是一份单场景验证，不代表所有企业、材料类型、知识提供方或 Agent 宿主都会得到相同结果。

## 实际链路

1. 一份真实企业技术资料同时包含稳定能力、仅适用于旧项目的变量、结构化表格和视觉素材。
2. 一次失败对照只取得扁平文字，丢失表格节点和图片，不能支持后续业务复用。
3. 后续整理把稳定事实写成 Agent 可直接取得的语义组件，把必须保留视觉真实性的内容作为媒体组件，并由唯一知识地图负责定位；来源文件继续承担来源证据，不作为每次任务都要重新解析的知识容器。
4. 一个独立新任务没有读取旧聊天，也没有重新取得来源文件。它从知识地图定位组件，读取实际内容，并结合本次招标要求判断哪些内容可以复用、哪些旧项目参数必须拒绝。
5. 任务最终生成可编辑 DOCX，保留结构化表格和真实图片。文件保存后重新打开并检查了内容、结构、分页与视觉素材，结果可继续用于正式业务。

## 五项测试

### 续接测试：通过，但收窄当前执行面

新任务不依赖旧聊天和来源文件，能够从稳定知识入口恢复可复用内容。它依赖的是明确的新任务输入、知识地图和可读组件，而不是上一项已完成任务的永久 Handoff。

这说明当前执行面对进行中的复杂工作仍有价值，但稳定知识跨已完成任务复用时不应额外维护一份当前状态。

### 真源测试：通过

不同事实由不同角色拥有：当前招标文件拥有本项目要求，企业知识组件拥有已确认的稳定事实，来源材料保留出处，知识地图只负责定位。新任务正确拒绝了旧项目变量，没有把索引、来源文件和当前要求混成第二真源。

稳定对象之间存在地图、组件、来源和当前任务的关系，并不要求它们共同拥有同一事实。“一个事实一个权威所有者”与对象关系可以同时成立。

### 结果测试：通过，并区分两种终态

组件写入、能够回读，只能证明技术写入完成。新的真实任务找到组件并生成可编辑、可检查、可继续使用的标书，才证明业务复用成功。

两种结果都可以是真实终态，但必须绑定各自意图，不能用前者冒充后者。

### 反馈测试：通过

扁平文字抽取丢失表格和图片的失败，直接改变了知识组件的边界和媒体处理方式。验证同时保留了宿主临时文件生命周期尚未解决的事实，没有把“项目目录不再重复保存资料”扩大成“没有任何本地副本”。

### 迁移测试：未通过验证

本轮在同一知识提供方和 Agent 运行环境中完成。组件关系和复用原则能否在另一知识提供方、本地文件载体或其他宿主中保持，仍需真实任务验证。

## 规则去向

| 规则 | 去向 | 原因 |
| --- | --- | --- |
| 当前执行面必须可替换 | 收窄 | 只要求未完成且方向敏感的工作拥有当前执行面；已经完成的稳定知识依靠正式真源和新任务输入复用，不维护永久 Handoff。 |
| 一个事实只能有一个权威所有者 | 保留 | 当前要求、稳定知识、来源和索引分工明确；对象关系没有要求多个对象共同拥有同一事实。 |
| 完成必须回到正式入口和可检查结果 | 保留并明确层级 | 技术写入完成和业务复用成功是两个不同结果，均需通过对应正式入口和可检查产物证明。 |
| 知识价值由后续真实复用证明 | 留在知识管理线路 | 本次任务直接支持该规则，但它仍是知识管理对“可检查结果”的专业化表达，不新增重复核心规则。 |
| 语义内容与视觉证据应采用不同载体 | 留在知识管理线路 | 该边界来自当前材料结构和知识提供方能力，尚未证明适用于其他线路。 |

## 尚未证明

- 多个组织、材料类型和连续任务中的稳定性；
- 知识更新、冲突、失效和退出能否保持同样清楚的所有权；
- 脱离当前知识提供方与宿主后的迁移结果；
- 在更大知识规模下，唯一地图是否仍是合适入口。
