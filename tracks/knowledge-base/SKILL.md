# 知识库 Skill

版本：2.0

## 先确定场景

知识库没有一套适用于所有人的目录和字段。开始工作前先确定：

- 谁使用：个人、团队、企业或当前项目；
- 什么内容需要长期复用；
- 当前任务的临时内容放在哪里；
- 谁能确认内容、谁能修改内容；
- 结果需要达到什么程度才算可以继续使用。

如果场景没有说清楚，不要先创建固定目录。先说明不确定之处，或者只做不改变原始材料的盘点。

## 共同目标

知识库要让人和 Agent 都能：

1. 看到材料从哪里来；
2. 区分原始材料、整理结果和已经确认的内容；
3. 找到与当前任务相关的内容；
4. 回到来源核对重要结论；
5. 在内容过期、冲突或需要修改时接手维护。

## 知识系统会接触四类内容

知识库相关工作通常会接触四类内容：

- **来源材料**：原始文件、网页、记录、数据或外部输入；
- **整理结果**：目录、摘要、拆分片段、索引和候选笔记；
- **可复用知识**：经过确认、可以在相似任务中引用的内容；
- **当前使用记录**：这一次任务选择了什么、修改了什么、还缺什么。它通常属于当前任务工作区，只通过引用连接回知识库。

载体可以是本地文件、云文档、数据库或其他工具。不要因为某个载体方便，就把四类内容混成一个没有状态的文件堆。

## 共同规则

### 原始材料可以很乱

允许从 Word、PDF、表格、图片、网页、聊天记录或已有笔记开始。先保留原样，再判断是否值得整理。解析失败不能导致原始材料丢失。

### 未知必须保持未知

如果无法判断内容是否正确、是否当前有效、是否允许复用，就标记为待确认或保留未判断状态。不要为了让笔记完整而猜日期、负责人、范围、权限或结论。

状态名称可以按场景选择。常见区别包括：未处理、候选、待确认、已确认、已替代、已归档。名称不是重点，重点是未确认内容不能伪装成已确认，已经失效的内容不能继续作为当前答案。

### 来源要能回去

需要被复用或会影响判断的内容，应记录来源和足够的定位信息。定位可以是文件路径、网页地址、页码、章节、表格、时间或其他能让人复核的方式。

低风险的个人随手记录不必强行填完整字段。风险越高、影响越大，来源、状态、适用范围和确认记录就应该越清楚。

### 长期材料和当前任务分开

当前任务可以引用知识库，但客户、金额、工期、临时承诺、当前草稿和交付文件不能自动写回长期知识。个人研究、企业业务和项目交付都需要自己的边界，具体目录由场景决定。

### 不覆盖，不假装完成

自动整理应保留中间结果，不直接覆盖原始材料。找不到、内容冲突、权限不明或解析失败时，明确报告缺口并停止相关动作。

## 处理流程

### 1. 接收

- 确认允许写入的范围；
- 保留原始材料和原始名称或接收记录；
- 记录必要的来源信息；
- 返回接收位置和当前状态。

不要在接收阶段顺手改写、删除或移动无法恢复的原始材料。

### 2. 盘点

先说明看到了什么：文件、章节、表格、主题、重复项、可能的冲突和缺失内容。盘点结果是中间结果，不是正式知识。

### 3. 整理

只有当内容边界清楚、确实需要复用时，才生成候选笔记或结构化结果。候选内容要保留来源和定位，并明确哪些部分需要人确认。

### 4. 核对

核对事实、来源、适用范围、时效、权限和场景边界。遇到冲突时保留两边材料并标记冲突，不替人猜哪一边正确。

### 5. 复用

查询时先使用场景已有的目录、标题、链接和全文搜索，再按需要使用属性或语义检索。只把符合当前场景要求且已经确认的内容作为正式依据。

返回结果时说明：

- 使用了哪些内容；
- 内容来自哪里；
- 当前状态是什么；
- 仍然缺什么确认；
- 结果写入了哪里。

### 6. 更新和退出

内容可能被更新、替代、撤回或停止使用。更新时保留旧版本与替代关系，不能只改正文而让人无法判断变化。

## 检索能力逐步增加

默认先用：

1. 目录、标题和链接；
2. 全文搜索；
3. 必要的属性过滤；
4. 关键词与语义的混合检索。

只有真实查询反复找不到内容时，才考虑向量检索。RAG 是先检索资料、再让模型基于资料回答的过程。向量索引和 RAG 都是可重建的辅助能力，不是知识库事实本身。

## 场景适配

共同 Skill 只规定底线。开始一个具体场景时，再补充：

- 目录或存储位置；
- 可用字段和状态名称；
- 谁负责确认和维护；
- 权限、保密和保留期限；
- 当前任务如何隔离；
- 什么结果可以交付。

个人知识库可以少字段、重隐私和阅读路径。企业知识库可能需要多人权限、负责人、有效期和正式凭证。投标工作区还需要客户、金额、工期、招标要求和交付格式。不能把这些场景字段写成所有知识库都必须拥有的字段。

## 失败安全和停止规则

遇到下面情况时，停止可能造成污染的动作，保留现场并说明原因：

1. 原始材料无法读取或解析；
2. 内容有冲突，无法判断当前答案；
3. 不清楚内容是否属于长期知识；
4. 不清楚用户是否有权读取或修改；
5. 当前任务变量可能写回长期材料；
6. 目录、字段或权限需要大规模调整；
7. 索引、脚本或 Agent 执行失败。

失败后必须做到：

- 原始材料仍然存在；
- 已生成的候选和中间结果仍然可查看；
- 返回失败步骤、原因和当前状态；
- 不把候选或待确认内容作为正式答案；
- 人可以接手修改、重试或换工具继续工作。

## 验收清单

- [ ] 人和 Agent 使用的是同一批必要材料
- [ ] 原始材料、整理结果、可复用知识和当前任务能够区分
- [ ] 重要内容可以回到来源核对
- [ ] 未知、冲突和过期内容不会被伪装成当前答案
- [ ] 当前任务不会自动污染长期知识
- [ ] 重复运行不会不断制造重复结果
- [ ] 删除高级索引后，核心材料仍然可用
- [ ] 找不到或无法确认时，系统会明确报告缺口
- [ ] 人可以在 Agent 失败后接手
