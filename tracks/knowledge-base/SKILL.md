# 知识库 Skill

## 第一性原理与当前实现

让人和 Agent 面对同一个知识对象，共同观测、操作、修正和演化它，让知识在使用中持续积累。当前实现使用同一套 Markdown 文件：正文表达语义，Frontmatter 跟随笔记记录属性，Wiki 链接表达关系，图片和附件引用保留证据位置。

Markdown 是当前承载方式，不是知识库的底层目的。

一篇长期知识笔记由四部分组成：

- **Markdown 正文**：写人和 Agent 共同理解的内容；
- **Frontmatter**：写这篇笔记的属性，如状态、来源、主体、有效期、负责人和标签；
- **Wiki 链接**：表达它与其他知识的关系；
- **图片和附件引用**：保留证据和补充材料的位置。

字段名称和目录由场景决定，但属性必须跟随笔记写在该笔记自己的 Frontmatter 中。正文不能被外部台账替代，索引不能成为第二套事实来源。

## 先确定边界

开始工作前确认：

- 当前使用者和场景是什么；
- 哪些内容要长期复用；
- 当前任务的临时内容放在哪里；
- 谁能确认事实、谁能修改笔记；
- 需要保留哪些原始证据和定位信息。

如果场景没有说清楚，不要擅自发明全局目录或字段。可以先做不改变原始材料的盘点，并把不确定处列出来。

## 原始材料可以很乱

Word、PDF、表格、图片、网页、聊天记录和已有笔记都可以作为输入。先原样保留原件，再判断是否值得形成 Markdown 知识。解析失败不能导致原始材料丢失，自动处理不能覆盖无法恢复的输入。

## 业务现场可以保留，架构不分叉

接收记录、内容盘点、候选片段、候选笔记、冲突记录和草稿可以作为业务现场保留，用于回溯和恢复。它们不是与 Markdown 知识并列的长期真相层。

只有经过确认、需要跨任务复用的内容才进入共同知识对象中的正式笔记。候选、待确认和失败现场必须能被人看见，不能被当作正式依据。

## 六步工作循环

### 1. 接收

- 确认允许写入的范围；
- 保留原始文件、原始名称和必要的接收信息；
- 返回接收位置和当前状态。

### 2. 盘点

说明看到了哪些文件、章节、表格、主题、重复项、冲突和缺失。盘点结果是工作现场，不是正式知识。

### 3. 形成候选

只有内容边界清楚且确实需要复用时，才生成候选 Markdown 笔记。候选笔记保留来源、页码、章节、表格或消息时间等定位，并把未知信息保持为未知。

### 4. 核对

核对事实、来源、适用范围、有效性、权限和场景边界。冲突时保留双方来源并标记待确认，不替人猜答案。

### 5. 写入正式知识

确认后的内容写入共同知识对象中的正式 Markdown 笔记：

- 正文写完整、独立可读的结论；
- Frontmatter 写已经知道且会影响使用的属性；
- Wiki 链接写可观察的知识关系；
- 图片和附件通过链接或索引写出证据位置。

### 6. 复用和维护

查询时先用目录、标题、Wiki 链接和全文搜索，再按需要使用属性、混合检索或向量检索。返回结果时说明使用了哪些笔记、来源在哪里、当前状态是什么、还缺什么确认。

笔记被更新、替代、撤回或归档时，保留来源和替代关系，不能只改正文而让人看不出变化。

## 属性和状态

Frontmatter 是笔记属性层，不是强制一次性填满的表格。只有会影响检索、判断、权限或维护的信息才值得写入。字段值没有证据时保持未知或省略。

状态可以按场景命名。常见状态包括 `unknown`、`candidate`、`needs-review`、`verified`、`superseded` 和 `archived`。状态的具体名字不是共性架构，状态必须表达的边界才是共性规则。

## 工作规则和当前任务的边界

Skill 或用户确认的长期工作规则描述“Agent 应该如何工作”。它们不保存企业事实，也不代替笔记属性。场景可以把这类文件命名为 RSI、行为规则或其他名称。

当前客户、金额、工期、临时承诺、草稿和交付物属于当前任务工作区。当前任务可以引用正式知识，但不能自动反写知识笔记、Frontmatter 或长期规则。

## 检索能力逐步增加

默认顺序是：

1. 目录、标题和 Wiki 链接；
2. 全文搜索；
3. Frontmatter 属性过滤；
4. 关键词与语义混合检索；
5. 向量检索；
6. RAG。

向量索引和 RAG 都是可重建的辅助能力：向量索引帮助按含义寻找，RAG 负责先取资料再生成回答。它们不能取代共同知识对象，也不能取代 Markdown、Frontmatter、Wiki 关系或原始证据。

## 停止规则

遇到下面情况时，停止可能污染知识的动作并报告原因：

1. 原始材料无法读取或解析；
2. 来源无法定位，或内容互相冲突；
3. 不清楚内容是否属于长期知识；
4. 不清楚用户是否有权读取或修改；
5. 当前任务变量可能写回长期知识；
6. 无法判断有效性、适用范围或状态；
7. 索引、脚本或 Agent 执行失败。

失败后必须做到：

- 原始材料仍然存在；
- 候选和处理现场仍然可查看；
- 返回失败步骤、原因和当前状态；
- 不把候选或待确认内容作为正式答案；
- 人可以直接编辑 Markdown、重试或换工具继续。

## 验收清单

- [ ] 人和 Agent 使用的是同一个知识对象，当前通过同一套 Markdown 文件暴露
- [ ] 正文、Frontmatter、Wiki 关系和附件证据都可观察
- [ ] 重要内容可以回到来源核对
- [ ] 未知、冲突和过期内容不会被伪装成当前答案
- [ ] 当前任务不会自动污染长期知识
- [ ] 重复运行不会不断制造重复结果
- [ ] 删除全文、向量和 RAG 辅助层后，核心知识仍然可用
- [ ] 找不到或无法确认时，系统会明确报告缺口
- [ ] Agent 失败后，人可以接手
