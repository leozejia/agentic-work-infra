# 知识库 Skill

## 目录结构

```
inbox/      原始材料落地处，保持原件不改动
notes/      经确认、可跨任务复用的正式 Markdown 笔记
archive/    已替代或过期的笔记（保留来源关系，不直接删除）
assets/     图片、PDF、扫描件等附件和证据文件
```

`inbox/` 未经核对不能直接引用。`notes/` 是持久真相层，写入前必须经过核对确认。`archive/` 不能重新变成当前依据。

## 先确定边界

开始工作前确认：

- 当前使用者和场景是什么；
- 哪些内容要长期复用；
- 当前任务的临时内容放在哪里；
- 谁能确认事实、谁能修改笔记；
- 需要保留哪些原始证据和定位信息。

如果场景没有说清楚，不要擅自发明全局目录或字段。可以先做不改变原始材料的盘点，并把不确定处列出来。

## 六步工作循环

### 1. 接收

- 确认允许写入的范围；
- 原样保留原件、原始名称和必要的接收信息；解析失败不能导致原始材料丢失；
- 返回接收位置和当前状态。

### 2. 盘点

说明看到了哪些文件、章节、表格、主题、重复项、冲突和缺失。盘点结果是工作现场，不是正式知识。

### 3. 形成候选

只有内容边界清楚且确实需要复用时，才生成候选 Markdown 笔记。候选笔记保留来源、页码、章节、表格或消息时间等定位，并把未知信息保持为未知。

### 4. 核对

核对事实、来源、适用范围、有效性、权限和场景边界。冲突时保留双方来源并标记待确认，不替人猜答案。

### 5. 写入正式知识

确认后写入 `notes/` 中的正式 Markdown 笔记：

- 正文写完整、独立可读的结论；
- Frontmatter 写已知且会影响使用的属性（状态、来源、有效期、负责人等）；字段值没有证据时保持未知或省略；
- Wiki 链接写可观察的知识关系；
- 图片和附件通过链接或索引写出证据位置。

属性必须跟随笔记写在该笔记自己的 Frontmatter 中，不能集中写在外部台账里。索引不能成为第二套事实来源。

候选片段、冲突记录和草稿留在 `inbox/` 作为业务现场，供回溯和恢复，不与 `notes/` 并列。

### 6. 复用和维护

查询顺序：目录/标题/Wiki 链接 → 全文搜索 → Frontmatter 属性过滤 → 混合检索 → 向量检索 → RAG。向量索引和 RAG 是可重建的辅助层，不能取代 Markdown、Frontmatter 和原始证据。

返回结果时说明使用了哪些笔记、来源在哪里、当前状态是什么、还缺什么确认。

笔记被更新、替代或归档时，移入 `archive/` 并保留来源和替代关系，不能只改正文而让人看不出变化。

## 停止规则

遇到下面情况时，停止可能污染知识的动作并报告原因：

1. 原始材料无法读取或解析；
2. 来源无法定位，或内容互相冲突；
3. 不清楚内容是否属于长期知识；
4. 不清楚用户是否有权读取或修改；
5. 当前任务变量可能写回长期知识；
6. 无法判断有效性、适用范围或状态；
7. 索引、脚本或 Agent 执行失败。

失败后必须做到：

- 原始材料仍然存在；
- 候选和处理现场仍然可查看；
- 返回失败步骤、原因和当前状态；
- 不把候选或待确认内容作为正式答案；
- 人可以直接编辑 Markdown、重试或换工具继续。

## 验收清单

- [ ] 人和 Agent 使用的是同一套 Markdown 文件
- [ ] 正文、Frontmatter、Wiki 关系和附件证据都可观察
- [ ] 重要内容可以回到来源核对
- [ ] 未知、冲突和过期内容不会被伪装成当前答案
- [ ] 当前任务不会自动污染长期知识
- [ ] 重复运行不会不断制造重复结果
- [ ] 删除向量和 RAG 辅助层后，核心知识仍然可用
- [ ] 找不到或无法确认时，系统会明确报告缺口
- [ ] Agent 失败后，人可以接手
