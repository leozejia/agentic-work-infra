# 知识库基础设施（Knowledge Base Infra）

为一切知识库工作提供统一规范。适用于任何载体（裸文件夹、在线文档平台、笔记应用、网盘——它们的本质相同：内容对象 + 组织关系 + 壳），不与任何具体产品绑定，也不依赖任何特定文件路径。

本 skill **自包含**：`references/` 内的规范文本即运行时依据，直接读取使用；修改规范在 skill 内完成并升版本号，旧版归档。当前版本 v0.2-candidate：经第二个真实领域验证前不宣称跨领域方法已冻结。

## 核心原则（先读，执法依据）

1. **第一读者是 AI**：知识库的主要消费者是 RAG 检索与 agent 调用，规则取向是可判定性 > 美观性。
2. **规则必须可判定**：每条规范写成「通过/不通过」的机械测试。禁止出现「清晰」「简洁」「合理」等形容词而不给出测试方法。
3. **不变量与策略分层，修订不对称**：不变量（生命周期独立测试、失真禁令、唯一真源与失效退出、名称最小充分语义、元数据、两级验收、反馈闭环、agent 红线）——降级或删除仅需一个有效反例（失败由规则本身导致、可复现、有记录）；新增或提升需 ≥2 个独立领域证据。策略（目录 ≤3 层、命名模板、300–2000 字异常提示、批次 ≤10、graveyard 等默认值）单一真实案例即可覆盖。
4. **默认不适配**：直接用不变量 + 默认策略投产；只有证据证明存在稳定领域方法缺口时，才做最小适配（详见规范第三章）。
5. **两级验收**：技术写入完成 = 检索命中 + 实际回读 + 结构完整（即时可验，全过才可报告写入完成）；业务复用已验证 = 真实任务成功使用（独立状态，纳入反馈闭环）。未验证对象不得当作「已验证知识」参与跨任务复用决策。复用成功只由真实任务证明。
6. **竞争力公式**：内容质量 × 检索精度 × 更新速度。存储本身不值钱。

## 工作流程

### 场景 A：为用户搭建新知识库

1. 读取 `references/知识库元管理规范.md`（v0.2-candidate 完整规范）。
2. 与用户确认领域与载体；**默认不做领域预适配**，直接按不变量 + 策略默认值搭建。
3. 生成三件套：逻辑结构骨架（目录型载体 ≤3 层）、`知识库管理规范.md`（含该库的策略覆盖，放入库根目录）、待裁决区 `inbox/`。
4. 命名满足名字可判测试（不打开内容即可判断）；专有名词字面出现；同义说法正文出现一次。

### 场景 B：领域适配（证据触发，非默认强制）

1. 先确认触发证据成立：同类问题反复失败 + 失败来自稳定领域方法缺口（非材料/权限/宿主能力）+ 缺口无法从通用规则推导 + 触发时机清晰。四条件不全，不启动适配。
2. 只增加修复已证明缺口的最小规则，仍须写成可判定测试。读取规范第三章与第二章策略表逐项处理。
3. 校准：20–50 条真实问题做检索测试（最低门槛）；再加回读核验与真实任务复用验证（两级验收完整）方冻结投产。
4. 修订规范时先读 `references/知识库架构讨论纪要-2026-08-28.md`（含 v0.2 升级与复审修正附录）理解规则推导背景；遵守规范第四章修订程序（不对称：证伪便宜、证实昂贵）。

### 场景 C：整理既有知识库（agent 执行）

1. 整理前完整读取库根目录的管理规范；规范未覆盖的情况移入待裁决区等人工裁决，不得自行发明规则。
2. 原子化按生命周期三测试执行：独立成立（不得存在无法解析的指代——内联必要上下文，或建立稳定可回读的对象关系，按是否制造重复真源择优）、生命周期独立（能独立复用/更新/失效；共同证明一件事的内容整体保留）、不可再分（再拆失去独立价值即停）。
3. 忠实编译允许：来源容器可转换为 agent 可用的语义内容（表格行列关系保留）；禁止改变事实、数值、含义、主体、限制、承诺。编译产物保留来源指向，写入后回读核验事实等价；不可逆丢弃须人工确认。
4. 篇幅 300–2000 字仅为异常提示：超出提示复查对象边界，不强制拆分。
5. 分批执行（默认 ≤10 对象/批，按对象复杂度与失败影响调整），逐批汇报，失败即停；只做可逆操作。
6. 失效内容必须退出有效检索空间并记录原因与替代路径；退出方式按平台能力与合规（目录型载体默认 `graveyard/` + `[废弃]` 前缀）；无平台策略与人工确认不执行不可逆删除。
7. 报告「写入完成」的唯一标准是技术三链全通（检索命中、实际回读、结构完整）；业务复用验证作为独立状态后续记录，不阻塞写入完成。

### 场景 D：质量复盘（周期性）

1. 抽取真实查询与真实复用记录，标记未命中、错命中、回读失败、复用失败案例。
2. 据此修库：改名称、补同义词、拆分、合并、失效退出；必要时修订规范本身并升版本号（遵守第四章修订程序，旧版归档）。

## 反模式（一票否决）

- 规范含不可判定的形容词而无测试方法。
- 按部门、来源或文件格式组织逻辑结构。
- 单对象塞多个独立生命周期主题（且并非共同证明一件事）。
- 改变事实/含义/主体/限制/承诺的「整理」。
- 失效内容留在有效检索空间；无来源指向、无法回读的对象算作已写入。
- 未验证对象被当作「已验证知识」用于跨任务复用决策。
- 把策略当不变量执行，拒绝载体或领域的合理偏离。
- 只入库不复盘。
