# 知识库元管理规范（v0.1）

**定位**：本规范定义跨行业不变的知识库管理规则。任何行业投产前，须由强模型按「第二章 定制区」完成行业化改写，经真实查询校准后，交执行整理的 agent 使用。

**执行者**：负责整理知识库的 AI agent。
**使用者**：知识库所有者、行业定制起草人。

---

## 第 0 条 执行前提

- agent 执行任何整理动作前，必须先完整读取本规范（含行业定制版）。
- 凡规范未覆盖、且无法从定制版中找到依据的情况：文件移入 `inbox/`，等待人工裁决，不得自行发明规则。
- 每完成一批整理（≤10 个文件）暂停汇报一次，经确认后继续。

## 第一章 不变量（行业定制时不得修改）

### 1. 原子化：三重测试

一篇文档合格，当且仅当同时通过以下测试：

1. **独立成立测试**：被单独检索出来、脱离上下文，目标读者仍能看懂。正文出现「如上」「参考前文」「按照上面的方案」等指代即不合格——将所指内容内联补入本篇。
2. **一问测试**：全文只回答一个具体问题，且标题能改写成这句疑问句。标题含「与」「及」「相关」等并列词时必须复查是否该拆。
3. **不可再分测试**：再拆将丢失必要上下文、或拆出部分失去独立意义——此时即为原子，停止拆分。

### 2. 量化字数带

- 默认单篇 300–2000 字。定制区可按文档类型调整数值，但「每类文档必须有明确字数带」这一点不可变。
- 超上限：按「总-分」拆为一篇索引篇 + 若干子篇；索引篇只放目录式摘要与子篇链接。
- 低于下限且无法独立扩写：并入主题最近的邻居篇。

### 3. 目录结构

- 目录深度 ≤ 3 层（根目录计为第 1 层）。
- 目录按「问题域」划分；禁止按部门、来源、文件格式划分。
- 超过 3 层：向上合并为主题目录。

### 4. 命名规则

- 格式：`主题-关键词-状态`（可附日期后缀）。示例：`ima-导入PDF-方法-202608.md`。
- **名字可判测试**：不打开文件、只看文件名与所在路径，即可判断该文件讲什么、是否可能回答某个问题。不通过即重命名。
- 文件名必须包含领域字面专有名词（见第一章第 6 条）。

### 5. 元数据头

每篇文档首行为一行元数据（行内或 YAML 均可）：

```
来源 | 日期 | 状态（有效/已废弃）| 类型
```

前三项为不变字段；「类型」取值由定制区定义。

### 6. 双检索友好

- **专有名词**（产品名、型号、法规编号、人名、行业术语）必须在标题与正文中字面出现——保证关键词全文检索可命中。
- 核心概念最常见的**同义说法**在正文出现至少一次——保证语义检索可命中。

### 7. 废弃与删除

- 过期内容不直接删除：移入 `graveyard/`，文件名加 `[废弃]` 前缀，元数据状态改为「已废弃」，注明废弃原因与替代文档路径。
- agent 在任何情况下不得直接删除资料。完全重复的，保留一份，并在元数据中记录被合并文件的路径。

### 8. 检索反馈闭环

- 每月（或定制区约定周期）做一次检索质量复盘：抽取真实查询日志，标记未命中与错命中案例，据此修复库（改标题、补同义词、拆分、合并、废弃），必要时修订规范本身。

### 9. agent 行为红线

- 不重写正文内容；只做归档、拆分、合并、重命名、补元数据。涉及内容改写须人工确认。
- 小批量执行（每批 ≤10 个文件），逐批校验，失败即停。
- 只做可逆操作（移动、重命名、追加元数据），不做任何不可逆操作。

## 第二章 定制区（投产前必须逐项填写）

**填写流程**：强模型基于行业样本资料起草 → 人工审核 → 用真实查询校准 → 冻结为 v1.0。

| 定制项 | 说明 | 默认值 |
|---|---|---|
| 文档类型清单 | 行业内容会出现的文档类型及各自定义 | 空 |
| 字数带 | 按类型覆盖第一章第 2 条默认值 | 300–2000 |
| 领域术语表 + 同义词表 | 术语与口语说法的映射，供检索与命名使用 | 空 |
| 命名词表 | 行业专有名词白名单 | 空 |
| 元数据扩展字段 | 如：法规编号、版本号、适用范围、客户行业 | 无 |
| 保留与废弃周期 | 按合规 / 时效要求设定 | 无 |
| 顶层目录骨架 | 按问题域给出的 1–3 层建议结构 | 空 |

### 定制与校准流程

1. 强模型研读行业样本资料，起草上表全部条目（产出必须仍写成可判定规则，禁止形容词）。
2. 取 20–50 条该行业真实问题，对整理后的库做检索测试，逐条记录命中 / 未命中。
3. 按 miss 案例修订规范与文件，重复测试直至命中率达标。
4. 冻结版本，投产；此后进入第一章第 8 条的周期性闭环。

## 第三章 反模式（一票否决）

- 规范中出现不可判定的形容词（「清晰」「简洁」「合理」）而不给出测试方法。
- 按部门、来源或文件格式组织目录。
- 目录嵌套超过 3 层。
- 单文件塞多个主题的「大杂烩」文档。
- 直接删除任何资料。
- 只入库、不复盘（缺失反馈闭环）。
