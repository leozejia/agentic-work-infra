# 知识库架构讨论纪要（2026-08-28）

> 本纪要沉淀一次关于「强模型时代知识库架构」的完整讨论。结论部分可直接引用，过程部分记录了认知如何演进——供后续行业定制时理解「规则为什么是这样」。

## 一、讨论演进路径

```
场景枚举（哪些场景需要知识库）
  → 四层架构（资料/组织/检索/应用）—— 第一版，偏抽象
  → 批判：「太抽象，如何落地？」
  → 第三/四层去魅：检索与应用是载体自带的能力，不是要搭的系统
  → 收敛为一份可执行规范（四层 = 往同一堆文件问的四个问题）
  → 上升到元层：元规范 + 行业二次定制
  → 引入本体论，为「元规范/定制」分层找到工程学先例
```

## 二、核心共识（按依赖顺序）

1. **本体论判断**：一切知识库产品 = 文件 + 文件夹 + 壳。ima、飞书、Obsidian、裸文件夹只是壳的厚度不同。架构讨论必须下沉到文件本身；壳的特效不构成方法论。
2. **第一读者是 AI**：强模型时代，知识库的主要读者从「人」变为 agent / RAG。这改变所有规则的取向：可判定性 > 美观性。
3. **四层收敛为两个动作**：
   - 人要做的：资料层（原子化）、组织层（扁平目录 + 可判命名）；
   - 载体自带的：检索层（关键词 + 语义向量）、应用层（RAG / Agent 工具调用）。
   - 后两层的价值不是「要去搭」，而是「解释前两层纪律为什么值得」——它们是甄别伪架构的试金石。
4. **规则必须可判定**：agent 整理不好的根因是规则里有形容词。每条规范必须写成「可通过 / 不通过」的测试：三重原子化测试、名字可判测试、量化字数带。
5. **两层规范结构**（本轮新共识）：元规范定义跨行业不变量；进入具体行业前由强模型按领域特性二次定制，经真实查询校准后投产。
6. **竞争力公式**：知识库价值 = 内容质量 × 检索精度 × 更新速度。存储本身不值钱。

## 三、方法论价值（讨论过程本身）

本次讨论走完了一个完整的螺旋：

**去魅（承认本质）→ 分层（建立结构）→ 最小化动作（落地为规则文件）→ 再抽象（元规范，可跨行业复用）**

从具体（场景）出发，经抽象（四层架构），被现实批判拉回具体（怎么落地），最终在更高层面完成抽象（元规范 + 行业定制）。这一模式可作为今后讨论同类「方法论落地」问题的模板：**抽象若无落地动作即无效；落地若无再抽象即不可复用。**

## 四、理论锚点：本体论（ontology）

- **哲学本义**：研究「存在本身」及其基本分类的学科，属形而上学，源自亚里士多德的「第一哲学」（being qua being，存在之为存在）。
- **工程权威定义**（知识工程 / AI 领域引用最高）：
  - Gruber（1993）：「本体是对概念化的显式规范」（An ontology is an explicit specification of a conceptualization）。
  - Studer 等（1998）补充两个关键词：「对**共享**概念化的**形式化、显式**规范」。
- **工程含义**：本体 = 概念 + 属性 + 关系 + 约束，是让机器可共享、可推理的分类骨架。
- **分层先例**（对应我们的两层规范）：上层本体（Cyc、SUMO、Dublin Core）定义跨领域通用概念；领域本体（医学 SNOMED CT、金融 FIBO）在各行业内做特化。**元规范 ≈ 上层本体；行业定制 ≈ 领域本体。** 我们的方案有成熟先例，不是发明。
- **中文语境的引申义**：「本体论式追问」常泛指「这个东西归根结底是什么」。本讨论开头的判断——「知识库本质是文件 + 文件夹」——就是一次本体论追问。

## 七、附录：v0.1 → v0.2 升级评估（同日，Bidwise 实践反馈触发）

**触发**：Bidwise（招投标领域）项目 agent 对 v0.1 提出 6 条修订建议，其核心质问成立——**v0.1 把经验性整理策略误写成了跨领域不变量**（固定字数、目录深度、命名格式、禁止内容转换、统一 graveyard 废弃，均属载体或领域特异的策略层）。

**六条判定与处置**：

1. 字数带降为异常提示（接受）——组件真实边界是生命周期独立（能独立复用/更新/失效）；证据组件、参与语义的表格与交叉引用必须整体保留，字数带在此直接出错。
2. 目录深度与命名格式降为策略（接受）——「≤3 层」「主题-关键词-状态」是文件系统载体的实现细节；数据库/标签型载体中层级与文件名不存在。不变量保留为「名称最小充分语义」（名字可判测试）。
3. 「不得重写正文」改为「失真禁令」（接受，最尖锐）——v0.1 想防幻觉却把忠实编译也禁了；正确靶子是失真（改变事实/含义/主体/限制/承诺），不是「改写」动作。附加核验守卫：来源指向 + 回读核验事实等价 + 不可逆丢弃须人工确认。
4. 废弃不统一 graveyard（接受）——不变量是「失效内容退出有效检索空间 + 动作可追溯」；退出方式（归档/删除/审计留存）由平台能力与合规决定。
5. 验收扩展为四链（接受，真正升级）——检索命中 ≠ 可用；必须 检索命中 → 实际回读 → 结构完整 → 真实任务复用成功 全通。「复用成功只由真实任务证明」入不变量。
6. 行业定制改为证据驱动适配（接受，附限定）——一份任务可同时含参数表/架构图/报价，行业标签不稳定决定处理方法；但「行业无用」同样是未证明假设，正确表述：适配轴本身是可证伪假设，默认不适配，证据触发最小适配。

**方法论收获**（本次升级对元方法论本身的贡献）：

- 不变量与策略必须分层，且修订权限不同：不变量需 ≥2 个独立领域证据，策略单一领域证据即可（v0.2 新增第四章「规范自身修订程序」）——strategy 冒充 invariant 的根源是缺自我修订程序。
- 实践反哺理论的闭环首样本：Bidwise 作为第一个真实领域，其 knowledge-method.md 的「组件按生命周期划分」「写入后回读」「复用由下一份真实标书证明」被元规范吸收抬升，验证了「行业定制 → 反哺元规范」的路径可行。
- v0.1 见 `archive/知识库元管理规范-v0.1.md`；v0.2 全文见《知识库元管理规范.md》。

## 八、附录：v0.2 复审修正 → v0.2-candidate（同日，Bidwise 二次复审触发）

Bidwise 侧对 v0.2 做结构化复审，结论 Keep（方向正确、不新增实体），提出四点核对，经评估全部成立：

1. **不变量修订规则违反可证伪原则**（最锋利）：波普尔不对称——全称命题不可证实、一个有效反例即可证伪。v0.2 写的「修改不变量需 ≥2 领域证据」把方向写反了；且 v0.2 自己依据单一领域（Bidwise）证据降级了多项不变量，按其自身规则即违规——自指矛盾。修正：降级/删除不变量一个有效反例即可（有效反例定义：失败由规则本身导致、可复现、有记录）；新增/提升才需 ≥2 领域证据。
2. **「写入完成」与「业务验证」混为一谈**：要求真实任务复用成功才算写入完成，导致新知识在下次业务出现前状态永久悬置。修正：拆为「技术写入完成」（命中/回读/结构，即时可验）与「业务复用已验证」（独立状态，纳入反馈闭环）；「复用成功只由真实任务证明」保留，改约束「已验证」宣称而非「写入完成」宣称。
3. **强制内联与唯一真源冲突**：v0.2 不变量 1 要求发现指代必须内联，与不变量 3 唯一真源潜在矛盾——大规模内联即重复真源。修正：靶子改为「无法解析的指代」，解法二选一（内联必要上下文 / 稳定可回读的对象关系），按是否制造重复真源择优。
4. **批量 ≤10 误留红线**：对象可能是一行笔记也可能是媒体组合，数量不稳定代表风险——文件时代残留。修正：红线只保留「逐批校验、失败即停」；≤10 降为策略默认值，按对象复杂度与失败影响调整。

**方法论收获**：

- 元规范同样受可证伪原则约束；修订程序必须不对称（证伪便宜、证实昂贵）。规范凡自我引用，必须先过自身规则——v0.2 的自指矛盾是最好的教训。
- 状态机要按「可验证时点」切分：写入时可验的（技术完成）与使用时才可验的（业务验证）必须分开建模，否则产生永久悬置状态。
- 措辞的一致性审计：「内联」与「唯一真源」这类跨条款冲突，需要在修订后做一次全文冲突扫描。
- 版本命名引入 candidate 级：跨领域方法在第二个真实领域验证前不宣称冻结——与「未验证的假设老实叫假设」的立场一致。

**当前状态**：v0.2-candidate。下一步：第二个真实领域验证；验证通过后移除 candidate 标记。
