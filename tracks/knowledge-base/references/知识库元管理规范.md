# 知识库元管理规范（v0.2-candidate）

中文 | [English](知识库元管理规范.en.md)

**定位**：定义跨领域不变的知识库管理规则与默认策略。规则分两层：**不变量**（跨领域成立；降级/删除仅需一个有效反例，新增/提升需 ≥2 个独立领域证据）与**策略**（默认值，单一真实案例即可修改，各知识库可覆盖）。不与任何载体、平台、产品绑定。
**候选声明**：本版本为 v0.2-candidate，经第二个真实领域验证前，不宣称跨领域方法已冻结。

**对象定义**：
- **内容对象**：任何可独立寻址的知识单元——原生笔记、语义文档、结构化表格、图片、媒体、证明页等。
- **组织关系**：对象之间的分类与定位方式（目录、标签、数据库关系、链接等），由载体决定。
- **壳**：提供权限、检索、交互与调用的载体层。
- 知识库最终由内容对象与组织关系构成；壳只影响实现方式，不产生方法论。

**执行者**：负责整理知识库的 agent。
**使用者**：知识库所有者、适配起草人。

---

## 第 0 条 执行前提

- agent 执行任何整理动作前，必须先完整读取本规范（含该库的策略覆盖版）。
- 凡规范未覆盖、且无法从策略覆盖中找到依据的情况：移入待裁决区，等待人工裁决，不得自行发明规则。
- 分批执行，逐批汇报（批次大小见策略层默认值）。

## 第一章 不变量（降级/删除：一个有效反例；新增/提升：≥2 个独立领域证据）

### 1. 原子化：生命周期独立测试

一个内容对象合格，当且仅当同时通过以下测试：

1. **独立成立测试**：被单独检索出来、脱离上下文，目标读者仍能看懂其内容与适用边界。正文不得存在**无法解析的指代**（「如上」「参考前文」等）。消除指代有两种方式，按此择优：内联必要上下文，或建立**稳定可回读的对象关系**（复用时经知识入口能定位并读取被指对象）。内联会制造重复真源时用关系；关系无法保证可回读时才内联。
2. **生命周期测试**：该对象能被独立复用、独立更新、独立失效。必须共同出现才能证明一件事的内容（顺序、层级、相邻表格、交叉引用本身参与语义时）保留在同一对象内，不拆分。
3. **不可再分测试**：再拆将丢失必要上下文、或拆出部分失去独立复用价值——即为原子，停止拆分。

组件边界由生命周期决定，不由篇幅、页数、标题层级或来源文件边界决定。

### 2. 失真禁令

- **允许**：忠实编译与结构化整理——把来源容器（Word、PDF、网页、压缩包等）转换为 agent 可直接使用的语义内容；表格的行列关系参与语义时保留为表格，不改写成列表或连续文本；转换只改变编码与载体，不改变内容。
- **禁止**：改变事实、数值、含义、主体、适用范围、限制条件与承诺。当前能力无法无损承载时，准确报告受阻与影响，不自行降级或发明替代。
- **核验守卫**：编译产物必须保留来源指向（真实来源名称与定位）；写入后从知识入口回读核验与来源的事实等价；不可逆丢弃来源信息须人工确认。

### 3. 唯一真源与失效退出

- 同一知识只有一个有效版本：完全重复的保留一份，并记录被合并对象的路径。
- 失效内容必须**退出有效检索空间**（不得再被常规检索当作有效知识命中），且处理动作可追溯（记录失效原因与替代对象路径）。
- 退出方式（归档、删除、外部审计留存）由平台能力与合规要求决定；agent 不得执行平台策略与合规之外的不可逆删除。

### 4. 名称最小充分语义

- **名字可判测试**：不打开内容、只看名称与所在逻辑位置，即可判断该对象讲什么、是否可能回答某个问题。不通过即重命名。
- 名称保留核心对象与区分复用边界所需的限定词（型号、地区、有效期、用途等）；删除任何一词会变成泛称或产生歧义时不得删除；不使用无业务意义的编号、时间戳、工具状态。
- **双检索友好**：领域专有名词（产品名、型号、法规编号、人名、行业术语）必须在名称与内容主体中字面出现——保证关键词检索可命中；核心概念最常见的同义说法在内容中出现至少一次——保证语义检索可命中。

### 5. 元数据

每个内容对象携带可判定的元数据：**来源、日期、状态（有效/已失效）**。形式（文件头、属性字段、数据库列）由载体决定。

### 6. 两级验收

**技术写入完成**——三条全过方可报告「写入完成」：
1. **检索命中**：目标问题能定位到该对象；
2. **实际回读**：从知识入口能取得对象实际内容（非摘要、非占位、非清单）；
3. **结构完整**：元数据、来源指向、状态齐全。

**业务复用已验证**——该对象在下一次真实任务中成功使用，作为**独立状态**记录并纳入反馈闭环，不是「写入完成」的前置条件。复用未验证的对象可用，但不得作为「已验证知识」参与跨任务复用决策。复用成功只由真实任务证明。

### 7. 反馈闭环

周期性（默认每月）复盘：抽取真实查询与真实复用记录，标记未命中、错命中、回读失败、复用失败案例，据此修库（改名称、补同义词、拆分、合并、失效退出），必要时修订规范本身。

### 8. agent 行为红线

- 批次大小由对象复杂度、操作可逆性与失败影响决定（策略层默认值见第二章）；逐批校验，失败即停。
- 只做可逆操作；平台策略与合规明确允许并经人工确认的删除除外。
- 涉及改变事实与承诺的改写（非忠实编译）须人工确认。

## 第二章 策略层（默认值；任一知识库可用单一真实案例覆盖）

| 策略项 | 默认值 | 说明 |
|---|---|---|
| 目录深度 | ≤3 层 | 仅适用于目录型载体；标签、数据库关系型载体不适用 |
| 命名格式 | `主题-关键词-状态` | 默认模板；满足名字可判测试即可偏离 |
| 文字型知识篇幅 | 300–2000 字 | **异常提示信号**：超出提示复查对象边界，不强制拆分 |
| 文字型知识拆分 | 一问一对象 | 「标题能改写成一句具体疑问句」为文字型知识默认策略；证据组件等按生命周期测试 |
| 批次大小 | ≤10 对象/批 | 按对象复杂度与失败影响调整；红线只是「逐批校验、失败即停」 |
| 待裁决区 | `inbox/` | 目录型载体默认；其他载体用等效机制 |
| 失效区 | `graveyard/` + `[废弃]` 前缀 | 目录型载体默认；删除与审计留存按平台与合规 |
| 复盘周期 | 每月 | 可按业务节奏调整 |
| 逻辑组织轴 | 按问题域 | 禁止按部门、来源、文件格式组织——此条为不变量级的默认，偏离需证据 |

## 第三章 适配（取代 v0.1 的「行业定制强制」）

**适配轴是可证伪假设**：按行业适配、按任务适配、按知识类型适配、暂不适配——均为假设，无默认正确项。

1. **默认不适配**：用第一章不变量 + 第二章默认策略直接投产，不做预适配。
2. **证据触发适配**：满足以下全部条件才启动——同类问题反复失败；失败来自稳定的领域方法缺口（而非材料、权限或宿主能力缺失）；该缺口无法仅从通用规则推导；触发时机清晰。
3. **最小适配**：只增加能修复已证明缺口的最小规则，且仍须写成可判定测试（禁止形容词）。
4. **行业分类仅凭证据引入**：只有真实数据证明行业标签能稳定提高正确率时，才按行业适配；一份任务混合多种知识类型（参数表、架构图、报价、人员）时，行业标签不作为处理依据。
5. **校准流程**：取 20–50 条真实问题做检索测试（最低门槛）；再加回读核验与真实任务复用验证（第一章第 6 条两级验收完整）方冻结投产。

## 第四章 规范自身修订程序

- **降级或删除不变量**：一个**有效反例**即可触发。有效反例的定义：失败由规则本身导致（而非材料、权限或宿主能力缺失），且可复现、有记录。
- **新增或提升为不变量**：需 ≥2 个独立领域的实践证据。
- **修改策略与默认值**：单一真实案例即可。
- **每次修订**：旧版本归档至 `archive/`，版本记录写明依据与来源领域。
- **候选条款**：当前不变量集整体处于候选级，经第二个真实领域验证通过后移除 candidate 标记。

## 第五章 反模式（一票否决）

- 规范中出现不可判定的形容词（「清晰」「简洁」「合理」）而不给出测试方法。
- 按部门、来源或文件格式组织逻辑结构。
- 单对象塞多个独立生命周期主题、且这些主题并非共同证明一件事。
- 改变事实、含义、主体、限制或承诺的「整理」。
- 失效内容留在有效检索空间。
- 无来源指向、无法回读的对象被算作已写入。
- 未验证对象被当作「已验证知识」用于跨任务复用决策。
- 只入库、不复盘（缺失反馈闭环）。
- 把策略当不变量执行，拒绝载体或领域的合理偏离。
