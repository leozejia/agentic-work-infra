# Agent 协作开发治理

中文 | [English](governance.en.md)

## 目标

Agent 可以承担设计、编码、测试和调试中的大量劳动，但开发治理仍要保证四件事：用户意图没有漂移，系统事实只有一个所有者，设计没有为局部症状失控扩张，完成由真实交付证明。

治理对象不是 Agent 的每一步推理，而是目标、正式状态、不可逆决定和验收责任。

## 从用户结果开始

每个产品或里程碑先写一句用户可检查的结果：

```text
某类用户提供什么
  -> 系统完成什么真实工作
  -> 用户得到什么可继续使用的结果
```

同时说明：

- 哪些风险和决定必须交给人；
- 当前明确不做什么；
- 哪些证据能够证明结果已经发生。

模块、页面、Agent 数量、代码量和任务清单都不是产品结果。实现中发现目标已经改变时，先更新产品事实和验收，再继续扩展。

## 真源按职责分层

长期项目至少需要区分以下角色，具体载体由项目决定：

- **项目宪法**：短而稳定的边界、禁区和权威读序；
- **产品事实**：用户、产品目标、行为边界和成功标准；
- **架构事实**：长期技术边界、正式状态和所有权；
- **当前执行面**：当前里程碑、已接受基线、下一动作和停止点；
- **运行入口**：构建、安装、发布、恢复和真实环境操作；
- **历史记录**：已经完成、失败或失效的过程证据。

聊天、日志和旧 Handoff 不能成为长期真相。每条规则只保留一个权威来源；其他位置只引用，不复制后各自演化。外部 Skill 和个人习惯只有写回项目正式文档后，才成为项目约束。

## 最小充分正确的设计

正确设计不是代码最少，也不是抽象最多，而是当前阶段下责任边界正确、成本可控、能够真实交付。

新增持久状态、fallback、兼容层、状态机、队列、后台服务、内部 Agent、协议或通用抽象前，回答五个问题：

1. 它解决了哪个已经发生的用户问题或维护问题？
2. 引入后谁是唯一真源和唯一写入者？
3. 官方能力、平台能力或现有结构为什么不够？
4. 不实现会造成什么可观察损失？
5. 用什么真实验收证明它必要且正确？

“以后可能需要”“更完整”“更工程化”和“多一层更安全”不能通过变更门。优先复用官方或现有正确路径，只治理项目真正需要拥有的部分。

## 正式状态与临时控制面

用户文件、已确认决定、正式业务数据和交付产物可以成为持久真相。候选项、运行日志、加载状态、进度、缓存、中间文件、预览和未确认推断默认只是临时控制面。

临时状态不能覆盖正式内容，也不能因为界面需要展示就升级成第二套业务模型。确需持久化时，必须定义生命周期、清理规则、唯一写入者和恢复语义。

## 当前执行面

中长任务使用一个可替换的当前执行面续接，不让聊天承担项目状态。它只需要保存：

- 一句话用户结果；
- 当前里程碑与非目标；
- 已接受和未接受的部分；
- 下一项精确动作与停止点；
- 验收证据；
- 当前代码与提交边界。

完成或失效后归档。长期规则先回到产品或架构真源，再由新的当前执行面引用。

## 实现与审查

实现前读取权威文档和工作树状态，未知修改默认属于用户或其他任务。每个变更文件都必须能由当前用户结果解释，不能顺手清理无关模块。

审查先问：

- 是否仍然服务原始用户结果？
- 是否新增第二真源或用 fallback 掩盖失败？
- 是否把内部状态暴露成产品概念？
- 是否因假想未来引入抽象？
- 是否有旧失败、新通过的行为证据？
- 是否走过对应的真实运行环境？

高风险或跨边界变更不能只由实现者解释完成，需要独立审查或人工验收。

## 停止局部补丁的信号

出现任一信号时，停止叠加条件，回到目标、真源和责任边界重新设计：

- 同一用户症状修复后再次出现；
- 一个缺陷需要多个新持久状态才能解释；
- fallback 或恢复逻辑进入正常主路径；
- 多个模块维护同一业务事实；
- 修复范围持续扩大，却没有更接近用户交付物；
- 测试只能证明实现细节，不能证明用户结果。

正确重构通常删除错误抽象或合并所有权，而不是增加更多守卫。

## 完成条件

验证可以从静态检查和最小回归开始，但最终必须走到正式产品入口、真实环境、真实数据和用户可检查交付物。Mock、fixture、成功提示、退出码和文件存在只能提供局部证据。

完成意味着：用户通过正式入口得到目标结果；关键风险可见；正式状态可审计；未完成部分没有伪装成功；下一位工程师不依赖聊天也能继续。

## 不迁入公共方法的内容

- 单个产品的架构、状态模型、运行命令和发布流程；
- 服务器、端口、域名、网络拓扑和本机配置；
- 特定框架、测试工具、模型或 Agent 的版本偏好；
- 某次事故的完整日志、客户数据和内部凭证；
- 为一个项目定制的安全禁区和回滚脚本。

这些事实继续由真实项目拥有，只把跨项目仍成立的治理约束带入本线路。
