# Agent-Assisted Media Production

[中文](method.md) | English

## Goal

This method does not optimize bulk content generation. It turns a signal into work the author is willing to own, then lets channel outcomes influence later judgment.

The complete path is:

```text
Signal
  -> primary sources and personal experience
  -> author judgment
  -> canonical article
  -> channel derivatives
  -> human-authorized public action
  -> real feedback
  -> revised judgment or method
```

File count, generation speed, and platform status ledgers cannot substitute for any step.

## Six Roles

A content task separates at least six roles. Different files or systems may carry them; a project does not need to copy another project's directory structure.

1. **Current execution surface**: stores only the current line of work, accepted baseline, independent question, next action, and stopping point. It supports continuation and does not retain full history.
2. **Long-term thesis**: stores the question a series or topic studies, relationships between its independent questions, the shared evidence boundary, and track-specific constraints.
3. **Factual sources**: store the primary material, time boundary, and uncertainty that the canonical article relies on. Social posts may supply leads, but do not automatically support critical claims.
4. **Canonical copy**: stores the complete argument, evidence, boundary, and conclusion. The author owns this one complete claim.
5. **Channel derivatives**: select, shorten, or reorganize canonical copy for different reading contexts. They do not create parallel arguments or add facts.
6. **Live platform state**: publication, links, performance, and interaction belong to the platform. Read current facts when making a decision instead of copying them into a permanent repository ledger.

Candidate images, previews, crawl logs, layout caches, and automation runtime state are temporary. Only selected deliverables and feedback that changes the method become durable assets.

## Topic Decision Gate

Lock four things before drafting:

- **Triggering fact**: What happened? Which parts are verified, and which parts are personal experience or inference?
- **Author judgment**: What single causal judgment does the author want to make? A list of questions is not a position.
- **Reader relationship**: Which readers are living through this tension, and what would understanding it change for them?
- **Evidence boundary**: Which material directly supports the judgment, and what evidence would refute or narrow it?

A long-running series also identifies the independent question this article resolves in the causal chain. A trend or project experience that stands on its own may become an essay. It does not need a forced connection to a series.

When these four points remain unsettled, continue discussion or research. Do not create canonical copy to replace judgment.

## From Canonical Copy to Channels

Complete the canonical article before deciding whether a channel version is needed. Each channel solves its own reading problem:

- A short post selects one angle worth public discussion instead of summarizing the full article.
- Image cards turn the same argument into mobile reading steps instead of shrinking type to fit the full article.
- Long-form channels reuse canonical copy by default and receive a separate rewrite only when the core argument needs a different structure.
- Images, audio, and video are created only when they improve discovery, understanding, or action. They are not default decoration.

Every channel version must trace back to the canonical article or its sources. When a new fact or judgment appears, update the canonical source first, then regenerate affected derivatives. Do not patch only one platform version.

## Automation and Human Responsibility

Research is read-only by default. Automation may perform repeatable, inspectable actions such as rendering, format checks, asset upload, or draft filling. Prior authorization does not imply current authorization.

Public publishing, interaction, payment, and other irreversible actions follow the person's current intent. When a platform is fragile or mistakes are costly, separate filling, saving a draft, and publishing into independently inspectable actions. Leave a final review surface for the person.

## Feedback

Feedback becomes an asset only when it changes later work:

- factual errors change source requirements or evidence boundaries;
- author edits change canonical copy or voice calibration;
- channel misreadings change how derivatives are built;
- automation incidents change an authorization gate or tool contract;
- platform performance informs the current decision unless repeated evidence supports a stable mechanism.

Do not store follower counts, links, publication state, calendars, or monthly reports to prove continued operation. Raw feedback remains on the platform. The public method keeps only rules that still need to run after validation.

## Completion

A media task is complete only when the following conditions match the current scope:

- the current claim, evidence boundary, and non-goals are explicit;
- canonical copy stands on its own, and channel versions add no facts;
- final assets can be used by the target channel;
- public actions match the person's current authorization;
- unverified publishing results and platform performance are not presented as success;
- the next agent can recover current state from the formal entry point without old chats.

## Excluded from the Public Method

- author identity, fixed tone, fixed hooks, and aesthetic preferences;
- personal articles, topic conclusions, account state, and platform links;
- current selectors, browser configuration, and publishing commands for one platform;
- image dimensions, algorithm weights, publishing times, and other changeable experience;
- crawl queues, candidate news pools, traffic ledgers, and permanent publishing dashboards.

These may exist in a real media project. One case cannot promote them into cross-project rules.
