# Agent 协作媒体生产方法

中文 | [English](method.en.md)

## 目标

本方法解决的不是怎样批量生成内容，而是怎样让一个信号在 Agent 协作下变成作者愿意负责的作品，并在渠道分发后继续影响下一次判断。

完整链路是：

```text
信号
  -> 原始来源与个人经验
  -> 作者判断
  -> 完整正文
  -> 渠道衍生物
  -> 人工授权的公开动作
  -> 现实反馈
  -> 下一次判断或方法修正
```

任何环节都不能用文件数量、生成速度或平台状态台账代替。

## 六种角色

同一内容任务至少区分六种角色。角色可以由不同文件或系统承载，不要求复制某个项目的目录结构。

1. **当前执行面**：只保存当前主线、已经接受的基线、当前独立问题、下一动作和停止点。它服务续接，不保存完整历史。
2. **长期命题**：保存系列或主题真正研究的问题、问题之间的关系、共同证据边界和特有约束。
3. **事实来源**：保存正文实际依赖的原始材料、时间边界与不确定性。社交内容可以提供线索，不能自动成为关键结论的证据。
4. **正文真源**：保存完整论点、证据、边界和结论。作者只需要对这一份完整主张负责。
5. **渠道衍生物**：从正文选择、缩写或重组内容，适应不同阅读场景，不建立平行论点，也不增加新事实。
6. **平台实时状态**：发布、链接、表现和互动由平台拥有，需要决策时读取当前事实，不复制成仓库里的永久台账。

候选图、预览、抓取日志、排版缓存和自动化运行状态属于临时过程。只有最终交付素材或确实改变方法的反馈才进入长期资产。

## 选题决策门

开始写作前必须锁定四件事：

- **触发事实**：发生了什么，哪些部分已经核实，哪些只是个人体感或推测？
- **作者判断**：作者真正要说的一个因果判断是什么？问题清单不能代替观点。
- **读者关系**：哪类读者正处在这个矛盾里，理解它会改变什么？
- **证据边界**：哪些材料直接支持判断，什么事实会推翻或缩小它？

长期系列还要说明本篇解决了因果链上的哪个独立问题。热点或项目经历只要能够独立成立，可以直接成为随想，不为制造宏大感强行进入系列。

四件事没有锁定时继续讨论或研究，不创建正文来替代思考。

## 从正文到渠道

正文先完整成立，再决定是否需要渠道版本。每个渠道只解决自己的阅读问题：

- 短帖选择一个值得公开讨论的切面，不摘要全文；
- 图文卡片把同一论点拆成移动端阅读节点，不靠缩小字体塞入全文；
- 长文渠道默认复用正文，只有核心论证确需重组时才单独改写；
- 图片、音视频只有在帮助点击、理解或操作时才制作，不作为默认装饰。

渠道版本必须能够追溯到正文或来源。发现新事实或观点时，先更新正文真源，再重新生成受影响的衍生物，不能只修某个平台版本。

## 自动化与人的边界

研究阶段默认只读。自动化可以执行可重复、可检查的动作，例如渲染、格式检查、上传素材或填充草稿，但不能从历史授权推导本次授权。

公开发布、互动、付费和其他不可逆动作服从人的当次意图。平台机制脆弱或误操作成本高时，把“填充”“保存草稿”“正式发布”拆成可独立检查的动作；自动化完成后给人保留最终审阅面。

## 反馈怎样回流

反馈只有在改变下一次工作时才形成资产：

- 事实错误改变来源门槛或证据边界；
- 作者修改改变当前正文或个人表达校准；
- 渠道误读改变衍生方式；
- 自动化事故改变授权门或工具契约；
- 平台表现只用于当次判断，除非多次证据支持一条稳定机制。

不为了证明“持续运营”保存粉丝数、链接、发布状态、日历或月报。原始反馈留在平台，公共方法只保存经过验证后仍需执行的规则。

## 完成条件

一次媒体任务只有在以下条件与本轮范围一致时才算完成：

- 当前主张、证据边界和非目标明确；
- 正文真源独立成立，渠道版本没有新增事实；
- 最终素材可以被目标渠道实际使用；
- 公开动作符合人的当次授权；
- 未验证的发布结果或平台表现没有被包装成成功；
- 下一位 Agent 能从正式入口恢复当前状态，而不依赖旧聊天。

## 不迁入公共方法的内容

- 作者人格、固定语气、固定 Hook 和审美偏好；
- 个人文章、选题结论、账号状态和平台链接；
- 某个平台当前选择器、浏览器配置和发布命令；
- 图片尺寸、算法权重、发布时间和其他会变化的经验；
- 抓取队列、候选新闻池、流量台账和永久发布看板。

这些内容可以在真实媒体项目中存在，但不能被一个案例提升为跨项目规则。
