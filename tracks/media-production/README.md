# 媒体生产线路

## 线路问题

一个来自新闻、研究或个人经历的判断，怎样在 Agent 协作下形成可信作品、渠道衍生物和真实反馈，同时不让平台状态、个人内容和工作过程互相污染？

这条线路研究媒体生产方法，不保存作者文章、图片、账号信息、发布链接、流量记录或平台自动化配置。

## 本地验证场

个人媒体仓继续拥有真实内容、个人表达、渠道成稿、素材和平台操作方法。它是本线路的本地验证场，不是公共仓的依赖，也不需要为了验证迁移内容。

## 已观察到的候选主干

- 先区分信号、原始来源和作者判断，热点本身不能替代主张。
- 一篇完整正文拥有论点和证据真源；渠道版本只能选择、重组或缩写，不能创造正文不存在的事实。
- 作品资产与平台实时状态分开：仓库保存长期有用的内容，平台保存发布、链接和表现。
- 自动化可以准备草稿和检查格式，但公开发布、互动和不可逆决定服从人的当次授权。
- 反馈应改变下一次选题、论证或分发判断，不应被复制成永久状态台账。

这些判断来自一套个人媒体实践，当前仍是媒体线路规则。只有在其他独立线路中出现同一工作约束，才讨论进入跨领域候选。

## 当前方法与证据

- [Agent 协作媒体生产方法](method.md)：定义信号、作者判断、正文真源、渠道衍生、发布授权和反馈回流之间的关系。
- [系列文章的正文与渠道衍生验证](validations/article-derivation.md)：用一个已经完成的真实内容任务检查续接、真源、结果、反馈和迁移边界。

本线路只迁入角色、约束和脱敏结论。文章正文、作者档案、渠道配置、平台账号与自动化实现继续由原项目拥有。

## 需要验证

- 新 Agent 能否不依赖旧聊天恢复当前主张、证据边界和下一动作。
- 正文、来源、渠道衍生物和临时状态并存时，是否仍能选对真源。
- 平台反馈是否真的改善下一次工作，而不是只增加记录负担。
- 个人表达与通用媒体方法能否分开，使方法迁移时不复制作者人格。
