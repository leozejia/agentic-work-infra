# Agentic Work 的共同模型

## 第一性原理

> **Agent 时代的知识库，首先要构建一个人类和 Agent 都能同时观测、操作、修正、演化的共同知识对象，让知识在使用中持续积累。**

这句话是本项目的底层原则。它规定我们要共同维护什么，不规定所有场景必须使用什么目录、字段或工具。

## 项目研究什么

本项目研究人和 Agent 如何面对同一个知识状态，共同理解一件事，并在真实工作中继续使用、核对、修正和积累。知识库因此不是单纯的存储系统，也不是只为 Agent 服务的检索系统。

人和 Agent 可以有不同的交互通道，但不能各自维护一套互相竞争的内容：

- 人需要可浏览、可理解、可判断和可修改；
- Agent 需要可读取、可引用、可验证和可操作；
- 两者最终都要回到同一个知识对象。

## 从原则到当前实现

当前项目选择把共同知识对象写成 Markdown 文件，并让属性、关系和证据跟随笔记暴露出来：

```text
原始资料和真实经验
        ↓
语义整理与核对
        ↓
共同知识对象
  Markdown 正文 + Frontmatter + Wiki 链接 + 附件引用
        ↓
人类通道：Obsidian、文件系统和其他编辑器
Agent 通道：Skill、MCP、API 和其他正式工具
        ↓
使用、引用、纠正和补充
        └──────────────→ 回到共同知识对象
```

“语义整理与核对”可以由人、Agent 或二者共同完成。这里的编译不是必须购买一个平台，而是把原始资料变成一份可以持续理解和维护的共享语义记忆。每次查询不应该都从大文件和聊天记录中重新猜一遍。

Markdown、Frontmatter、Wiki 链接和 Obsidian 是当前实现，不是第一性原理。未来可以替换工具或文件界面，但不能丢掉共同观测、共同操作、共同修正和共同演化。

## 三个边界

### 共同知识对象：记录“这件事是什么”

- 正文写完整语义，让笔记离开聊天上下文后仍然能读懂；
- Frontmatter 写这篇笔记自己的属性，例如主体、状态、来源、有效期、负责人或标签；
- Wiki 链接写它与其他知识的关系，让关系对人和 Agent 都可见；
- 图片和附件通过链接或索引保留证据位置。

属性必须跟随笔记进入它自己的 Frontmatter。字段名和数量可以由场景决定，没有证据的值保持未知或省略。

### 工作规则：记录“应该如何工作”

Skill 和用户明确确认的长期工作规则，描述步骤、检查项、停止条件、权限边界和输出约束。它们不保存企业事实，也不代替笔记的正文、属性、关系和证据。

### 当前任务：记录“这一次发生什么”

客户、金额、工期、当前要求、临时承诺、草稿、交付文件和本次选择的知识，属于当前任务工作区。任务可以引用长期知识，但一次任务不能自动改变长期知识。

## 架构只有一条主线，业务可以保留现场

架构上的主线是：原始资料经过整理和核对，形成共同知识对象；共同知识对象被人和 Agent 使用，并在使用中继续修正和积累。

真实业务里可以保留接收记录、内容盘点、候选片段、候选笔记、冲突记录、草稿和失败现场。这些产物用于回溯、恢复和重新运行，但不是与共同知识对象并列的长期真相层：

- 原始材料是输入和证据；
- 候选与草稿是可回溯的工作现场；
- 确认后、需要长期复用的内容回到共同知识对象；
- 索引、缓存和生成结果都可以删除后重建。

因此，业务可以有中间过程，架构不需要中间真相。

## 检索辅助的位置

目录、标题、全文搜索和属性过滤是基础能力。向量索引、混合检索和 RAG 只解决“怎样更快找到和使用”这个问题：

- 向量索引是可重建的搜索辅助物；
- RAG 是先找资料，再基于资料生成回答的工作过程；
- 它们都不能成为人看不到、无法核对和无法维护的第二套知识状态。

## 共同底线

- 重要结论能够回到原始来源和可复核位置；
- 未知、冲突、待确认和过期内容保持显式；
- 自动处理不覆盖或删除无法恢复的原始材料；
- Agent 只修改明确授权的文件和目录；
- 当前任务不会污染长期知识；
- 失败后人可以继续编辑、重试或换工具；
- 结果由人或独立检查确认，不能只看 Agent 的“已完成”提示。

## 场景如何扩展

个人知识库、企业知识库、投标、研发和客服可以有不同的目录、字段、权限和 Skill。它们只在场景层增加差异：

| 维度 | 共性原则 | 当前场景自行决定 |
|---|---|---|
| 共同对象 | 人和 Agent 共同观测、操作、修正、演化 | 对象范围和确认人 |
| 知识表达 | 当前使用 Markdown、Frontmatter、Wiki 链接和附件引用 | 文件夹、字段名、命名方式 |
| 工作规则 | Skill 与用户确认的长期规则 | 业务步骤、审批和停止条件 |
| 当前任务 | 独立工作区、可引用、不可自动反写 | 客户、金额、工期、交付格式 |
| 检索辅助 | 可重建、不能成为第二真相 | 具体索引工具和触发阈值 |

场景文档用于验证这套模型，不得反过来创造第二个全局模型。

## 判断是否仍在主线上

1. 人和 Agent 是否面对同一个知识状态？
2. 知识正文、属性、关系和证据位置是否都能被人观察？
3. Skill 是否只规定工作方法，没有把事实藏进去？
4. 当前任务变量是否与长期知识分开？
5. 删除高级索引后，共同知识对象是否仍然可读、可查、可维护？
6. 失败后是否能从原始材料和已有笔记继续？

如果答案需要另一套隐藏知识系统才能成立，说明设计已经偏离主线。
