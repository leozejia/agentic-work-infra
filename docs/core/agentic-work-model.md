# Agentic Work 的共同模型

## 项目研究什么

本项目研究的不是“怎样给 Agent 建一个更快的搜索系统”，而是：

> **人和 Agent 如何通过同一套可观察的知识理解同一件事，并在明确的工作规则下完成可检查、可继续使用、失败后可以接管的任务。**

这条判断决定了项目的架构主线：知识不能一份给人看、另一份藏在索引里给 Agent 用。人和 Agent 必须面对同一份能够阅读、核对和维护的知识表达。

## 唯一的架构主线

```text
Markdown 知识文件
  ├── 正文：事情本身，人和 Agent 共同理解
  ├── Frontmatter：这篇笔记是什么，如何筛选和维护
  ├── Wiki 链接：它与哪些知识有关
  └── 图片/附件引用：证据和补充材料在哪里
        ↓
Skill + 用户明确确认的长期工作规则
        ↓
当前任务工作区与项目变量
        ↓
全文搜索、属性过滤、向量检索和 RAG 等辅助能力
```

这是项目当前唯一的共性设计。这里的“唯一”不是要求所有场景使用同一套目录或字段，而是不再同时维护另一套数据库式、索引式或 Agent 专用的知识架构。

## 四个边界

### 知识笔记：记录“这件事是什么”

一篇可长期引用的知识笔记使用 Markdown 文件承载共同理解：

- 正文写完整语义，让笔记离开原始上下文后仍能读懂；
- Frontmatter 写这篇笔记的属性，例如主体、状态、来源、有效期、负责人或标签；
- Wiki 链接写它与其他知识的关系，让关系对人和 Agent 都可见；
- 图片和附件用 Markdown 链接或索引保留证据位置，不能只藏在外部系统里。

属性必须跟随笔记进入该笔记自己的 Frontmatter。字段名称和字段数量可以由场景决定，字段的位置和归属不能改成外部台账或隐藏索引。没有证据的属性保持未知或省略，不能为了完整而猜。

### 工作规则：记录“应该如何工作”

Skill 和用户明确确认的长期工作规则，描述 Agent 的步骤、检查项、停止条件和输出约束。它们不保存企业事实，也不代替知识笔记的正文或 Frontmatter。

场景可以把用户确认的长期规则叫作“编标行为规则”、RSI 或其他名称，但这个名称属于场景，不是全局对象。当前任务的明确要求优先于长期规则；Agent 可以提出规则，但不能把自己的推断直接写成长期规则。

### 当前任务：记录“这一次发生什么”

客户、金额、工期、当前要求、临时承诺、草稿、交付文件和本次选择的知识，属于当前任务工作区。任务可以引用长期知识，但一次任务不能自动改变长期知识的事实、属性或关系。

### 检索辅助：帮助“更快找到和使用”

目录、标题、全文搜索和属性过滤是基础能力。向量索引、混合检索和 RAG 可以在真实查询失败后加入，但它们只服务于 Markdown 知识：

- 向量索引是可重建的搜索辅助物；
- RAG 是先找资料、再基于资料生成回答的工作过程；
- 二者都不能成为人看不到、无法核对和无法维护的第二套知识真相。

## 业务处理可以有中间结果

原始文件很乱时，业务流程可以保留接收记录、内容盘点、候选片段、候选笔记、冲突记录、草稿和失败现场。这些产物帮助人回溯、恢复和重新运行。

但它们不是架构上的并列真相层：

- 原始材料是证据输入；
- 候选和草稿是可回溯的工作产物；
- 经过确认、需要长期复用的内容要回到 Markdown 知识笔记；
- 任何索引、缓存或生成结果都可以删除后重建。

因此，业务允许有中间过程，架构仍然只有一条前进主线。

## 共同底线

- 重要结论能够回到原始来源和可复核位置；
- 未知、冲突、待确认和过期内容保持显式，不能被伪装成确定；
- 自动处理不覆盖或删除无法恢复的原始材料；
- Agent 只修改明确授权的文件和目录；
- 当前任务不会污染长期知识；
- 失败后保留现场，人可以继续编辑、重试或换工具；
- 结果由人或独立检查确认，不能只看 Agent 的“已完成”提示。

## 场景如何扩展

个人知识库、企业知识库、投标、研发和客服可以有不同的目录、字段、权限和 Skill。它们只在场景层增加差异：

| 维度 | 共性主线 | 场景自行决定 |
|---|---|---|
| 知识表达 | Markdown 正文、Frontmatter、Wiki 链接、附件引用 | 文件夹、字段名、命名方式 |
| 工作规则 | Skill 和用户确认的长期规则 | 业务步骤、审批和停止条件 |
| 当前任务 | 独立工作区、可引用、不可自动反写 | 客户、金额、工期、交付格式 |
| 检索辅助 | 可重建、不能成为第二真相 | 具体索引工具和触发阈值 |

场景文档用于验证这套模型，不得反过来创造第二个全局模型。

## 判断是否仍在主线上

拿一项真实工作检查：

1. 人和 Agent 是否面对同一份 Markdown 知识表达？
2. 知识正文、属性、关系和证据位置是否都能被人观察？
3. Skill 是否只规定工作方法，没有把事实藏进去？
4. 当前任务变量是否与长期知识分开？
5. 删除高级索引后，核心知识是否仍然可读、可查、可维护？
6. 失败后是否能从原始材料和已有笔记继续？

如果答案需要另一套隐藏知识系统才能成立，说明架构已经偏离主线。
