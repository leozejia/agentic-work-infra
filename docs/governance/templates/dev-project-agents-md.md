## 架构约束（不可违反）

<!-- 以下三条通用约束不要删除。
     开发项目特有约束预填在下方，按需删减。
     判断标准：违反这条，项目会出现用户可见的问题，或者无法安全修复。 -->

1. **授权边界**：Agent 只修改明确授权的范围，不能静默覆盖原始材料。
2. **显式不确定**：未知、冲突和待确认必须保持显式，不能伪装成确定。
3. **当前与长期分离**：当前任务可以引用长期知识，但不能把任务变量自动写回长期层。
4. **层边界不泄漏**：协议模型、领域模型、持久化模型和视图模型不得相互泄漏；数据在边界处完成校验和独立转换，不跨层共享可变状态。
5. **安全默认开启**：任何外部输入视为不可信；敏感信息不进入代码、日志或响应；权限遵循最小权限原则。
6. **为维护者保留上下文**：非显然的设计决策、已知缺陷和临时方案必须记录原因和移除条件；关键架构决策同步到 ADR，禁止留下缺少上下文的 TODO。
7. **内部删除优于兼容**：内部实现重构时直接删除过时代码，不增加兼容层或双写逻辑。对外稳定接口（API、数据库协议）的兼容性单独评估。
