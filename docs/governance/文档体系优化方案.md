## 问题 3：DESIGN.md 的定位

**非常好的提议**。DESIGN.md 应该作为**可选的架构层文档**。

### DESIGN.md 的角色

**什么时候需要 DESIGN.md？**

满足以下任一条件：
1. 项目有多个子系统需要说明职责边界
2. 有重要的架构决策需要记录理由
3. 有复杂的数据流或状态转换
4. 团队规模 > 2 人，需要架构共识

**什么时候不需要？**
- 小型项目（单一功能）
- 架构很简单（一目了然）
- 只有自己维护

### DESIGN.md vs. architecture/

**DESIGN.md**：
- **单文件**，5-20KB
- **概览性**：系统组成、职责边界、关键决策
- **稳定**：架构确定后很少改
- 适合：中小型项目

**architecture/**：
- **多文件**，每个子系统/决策一个文件
- **详细性**：每个文件深入一个主题
- **演化**：持续记录 ADR（Architecture Decision Records）
- 适合：大型项目、多人协作

### 推荐的分级策略

```
小型项目（单人，< 5K 行代码）：
  ✓ AGENTS.md
  ✓ README.md
  ? HANDOFF.md（如果需要交接）
  ✗ DESIGN.md
  ✗ architecture/

中型项目（小团队，5K-50K 行代码）：
  ✓ AGENTS.md
  ✓ README.md
  ✓ HANDOFF.md
  ✓ DESIGN.md（或 docs/architecture/overview.md）
  ✓ LESSONS.md
  ? architecture/（有复杂决策时）

大型项目（多团队，> 50K 行代码）：
  ✓ AGENTS.md
  ✓ README.md
  ✓ HANDOFF.md
  ✓ docs/architecture/（多文件）
  ✓ docs/product/
  ✓ docs/research/
  ✓ LESSONS.md
```

## 问题 4：文档体系的最优解

### 当前体系的问题

**agent-governance.md 的建议**：
> 要求每个项目都有 AGENTS.md、HANDOFF.md、architecture/、product/、research/

**问题**：
1. ❌ 没有区分项目规模
2. ❌ 没有说明"可选"和"必需"
3. ❌ 对小项目过度设计
4. ❌ 缺少 LESSONS.md
5. ❌ 缺少 DESIGN.md 选项

### 最优文档体系设计

#### 核心原则

1. **分层必需**：AGENTS.md → README.md → 其他
2. **按需扩展**：有内容再建，不建空目录
3. **规模适配**：小中大项目不同结构
4. **模板引导**：用 templates 而非硬性要求

#### 必需文档（所有项目）

```
AGENTS.md           # 项目宪法，Agent 的唯一入口
README.md           # 人类入口，快速上手
```

**判断标准**：Agent 读完这两个文件，能开始第一个任务。

#### 动态文档（按需要）

```
docs/HANDOFF.md     # 有交接需求时（多人/长期项目）
docs/LESSONS.md     # 开始用 Agent 后，有失败案例时
DESIGN.md           # 架构需要说明时（中型项目）
```

#### 分类文档（按内容类型）

```
docs/architecture/  # 有多个架构决策时（替代 DESIGN.md）
docs/product/       # 有产品决策需要记录时
docs/research/      # 有调研和验收矩阵时
```

### 具体建议矩阵

| 文档 | 小型 | 中型 | 大型 | 触发条件 |
|------|------|------|------|---------|
| **AGENTS.md** | ✓ 必需 | ✓ 必需 | ✓ 必需 | 有 Agent 参与 |
| **README.md** | ✓ 必需 | ✓ 必需 | ✓ 必需 | 所有项目 |
| **HANDOFF.md** | ? 可选 | ✓ 推荐 | ✓ 必需 | 需要交接、或间隔工作 |
| **LESSONS.md** | ? 可选 | ✓ 推荐 | ✓ 必需 | 开始有失败案例 |
| **DESIGN.md** | ✗ 不需要 | ✓ 二选一* | ? 可选* | 架构需要说明 |
| **architecture/** | ✗ 不需要 | ✓ 二选一* | ✓ 推荐* | 有多个架构决策 |
| **product/** | ✗ 不需要 | ? 可选 | ✓ 推荐 | 有产品决策 |
| **research/** | ✗ 不需要 | ? 可选 | ✓ 推荐 | 有调研需求 |

*注：DESIGN.md 和 architecture/ 二选一，中型项目推荐 DESIGN.md，大型项目推荐 architecture/

### 判断规则

**何时需要某个文档？**

问三个问题：
1. **必要性**：没有它，Agent 或人会做错决策吗？
2. **时效性**：它会持续更新吗？还是一次性的？
3. **替代性**：它的内容能合并到其他文档吗？

如果答案是：
- 必要 + 持续更新 + 不能合并 → 独立文档
- 必要 + 一次性 → 可能不需要单独文档
- 不必要 → 肯定不需要

## 优化后的文档体系

### 核心设计

```
必需层（2个文件）
  ├── AGENTS.md        # 入口，50-100 行
  └── README.md        # 快速上手

推荐层（按需要）
  ├── docs/HANDOFF.md  # 当前状态（多人/长期项目）
  └── docs/LESSONS.md  # 失败记录（有失败案例后）

可选层（按内容）
  ├── DESIGN.md        # 架构概览（中型项目）
  │   或
  ├── docs/architecture/  # 架构详细（大型项目）
  ├── docs/product/       # 产品决策
  └── docs/research/      # 调研验收
```

### 模板体系

```
docs/governance/templates/
├── agents.md             # 必需
├── readme.md             # 必需（新增）
├── handoff.md            # 推荐
├── lessons.md            # 推荐（新增）
├── design.md             # 可选（新增）
├── task-contract.md      # 工具
└── adr.md               # 工具（新增，ADR 模板）
```

替换原来的"要求每个项目都有..."，改为：

```markdown
## 文档分级策略

### 必需文档（所有项目）

**AGENTS.md** - Agent 的唯一入口
- 项目定位（是什么、不是什么）
- 架构约束（不可违反，5条以内）
- 修改和验证（必须运行的命令）
- 文档路由（其他文档在哪里）
- 长度：50-100 行

**README.md** - 人类入口
- 一句话介绍
- 快速开始
- 常用命令
- 项目结构（如果复杂）

**判断标准**：Agent 读完这两个文件，能开始第一个任务。

### 推荐文档（按需要）

**docs/HANDOFF.md** - 当前状态和下一步
- 何时需要：多人协作、长期项目、有交接需求
- 内容：当前在哪里、下一步做什么、关键文件
- 更新频率：每周或每次重要变更

**docs/LESSONS.md** - 失败记录和规则演化
- 何时需要：开始用 Agent 后，有重复失败案例
- 内容：规则 + 证据 + 出现次数
- 更新频率：每周 review 或发现重复失败时

### 可选文档（按复杂度）

**DESIGN.md** - 架构概览（中型项目）
- 何时需要：有多个子系统、有重要架构决策
- 内容：系统组成、职责边界、关键决策理由
- 替代方案：docs/architecture/overview.md

**docs/architecture/** - 架构详细（大型项目）
- 何时需要：有多个架构决策需要分别记录
- 内容：每个子系统一个文件、ADR 记录
- 替代：DESIGN.md（小项目）

**docs/product/** - 产品决策
- 何时需要：有产品判断需要记录
- 内容：PRD、交互决策、商业模式

**docs/research/** - 调研和验收
- 何时需要：有调研任务、需要验收矩阵
- 内容：调研报告、benchmark、验收清单

### 规模参考

| 规模 | 代码量 | 必需 | 推荐 | 可选 |
|------|--------|------|------|------|
| 小型 | < 5K 行 | AGENTS.md<br>README.md | HANDOFF.md* | - |
| 中型 | 5K-50K | AGENTS.md<br>README.md | HANDOFF.md<br>LESSONS.md | DESIGN.md<br>或 architecture/ |
| 大型 | > 50K | AGENTS.md<br>README.md | HANDOFF.md<br>LESSONS.md<br>architecture/ | product/<br>research/ |

*小型项目的 HANDOFF.md：如果是单人且持续工作，可以省略；如果有间隔或需要交接，建议加上。

### 使用 templates

**新建项目**：
1. 从 `templates/agents.md` 创建 `AGENTS.md`
2. 从 `templates/readme.md` 创建 `README.md`
3. 根据规模，选择性添加其他文档
4. **不建空目录**，有内容再建

**判断是否需要某文档**：
1. 没有它，Agent 或人会做错决策吗？
2. 它会持续更新吗？
3. 它的内容能合并到其他文档吗？

如果 1=是、2=是、3=否 → 需要独立文档
否则 → 不需要或可以合并
```
