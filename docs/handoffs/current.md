# 当前研究 Handoff

## 一句话结果

先找到人机协同长期工作的核心主干，再判断知识库、内容生产、Handoff、可视化面板和其他工作系统之间究竟是什么关系。

## 当前问题

> 一项工作要跨会话、跨工具和跨团队持续推进，最少必须保存和传递什么？

当前不讨论界面与产品实现，也不预设“内容管理位于知识库之上”。需要先证明不同领域是否真的共享同一种工作结构。

## 已接受基线

- 模型能够完成一次任务，不代表长期工作已经形成系统。
- 当前已观察到的共同风险包括目标漂移、上下文丢失、真源混乱、结果无法验收和反馈没有回流。
- “内容”可能只是工作资产的一种表现，不能因为媒体仓和知识库都保存文件，就断言两者存在上下级关系。
- “Agent 原生工作基础设施”是当前研究名称，不是已经完成定义的产品类别。
- 跨行业适用是候选假设，必须接受真实反例检验。

## 当前验证

从三个真实场景分别还原完整工作过程：

1. 内容创作：一个判断怎样从材料形成正文、渠道产物、发布结果和后续经验。
2. 企业知识库：资料怎样成为可检索、可回读、可复用并能退出有效空间的知识。
3. 投标/FDE：客户意图、企业材料、专业方法、交付结果和问题反馈怎样跨任务延续。

比较时只回答：每个场景为了持续工作必须保留什么、由谁判断、怎样验证、什么会失效。暂不统一文件结构和术语。

## 下一动作

为上述三个场景各选取一个已经发生的真实任务，画出从意图到反馈的实际链路；先记录事实与失败，不提炼通用模型。完成三份链路后，再比较共同结构和有效反例。

## 暂不决定

- 核心管理单元最终叫工作资产、工作对象、上下文还是其他名称。
- 知识库、内容系统和 Handoff 是平级视图、生命周期阶段还是不同系统。
- 最终交付是方法论、协议、Skill、可视化工作台，还是组合形态。

这些问题由真实案例决定，不在研究开始前锁死。
