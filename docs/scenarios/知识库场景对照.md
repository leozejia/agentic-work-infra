# 知识库场景对照

本文只用于检验共同框架，不定义新的全局目录或字段。

## 共同问题

个人知识库、企业知识库和项目工作区都要处理：

- 材料从哪里来；
- 当前内容是否只是候选结果；
- 哪些内容可以反复使用；
- 如何找到相关内容；
- 如何回到来源核对；
- 当前任务的修改是否会污染长期内容；
- 自动整理失败后能否继续。

## 场景差异

| 问题 | 个人知识库 | 企业知识库 | 项目工作区 |
|---|---|---|---|
| 主要使用者 | 一个人或一个家庭 | 多人、部门或合作方 | 当前项目成员 |
| 重要边界 | 隐私和个人习惯 | 权限、责任、合规和版本 | 客户、合同、交付和保密 |
| 长期内容 | 个人经验、资料和思考 | 公司能力、制度和已确认事实 | 通常不作为长期知识 |
| 临时内容 | 当前研究或写作 | 当前审批或业务任务 | 客户要求、金额、工期和草稿 |
| 确认方式 | 本人判断或引用来源 | 业务负责人、制度或正式凭证 | 项目负责人和交付验收 |

## 判断规则

只有在三个场景都成立的规则，才应该进入共同框架。例如：

- 原始材料不能被自动整理覆盖；
- 不确定内容不能伪装成确定；
- 结果应该能回到来源；
- 当前任务和长期材料要有边界。

只在企业出现的内容，例如部门负责人、证书有效期和多人审批，应留在企业场景。只在投标出现的内容，例如客户、金额、工期和招标要求，应留在投标场景。

## 当前实现顺序

共同表达已经固定为 Markdown 正文、Frontmatter、Wiki 链接和附件引用。先用企业知识库和投标作为真实验证场景，同时用个人知识整理检查是否出现企业特例；目录、字段和高级检索工具仍然只有在具体场景证明需要时才增加。
