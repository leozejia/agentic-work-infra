# 知识库到投标业务打通方案

## 当前卡点

企业用两份Word模板 + AI复制粘贴，能快速生成一份标书（90%内容）。但这不是规模化生产：

| 问题 | 后果 |
|---|---|
| 每次都要读取整份大Word文件 | AI每次重新判断哪些内容稳定、哪些失效、哪些只适用旧项目 |
| 一条知识更新不知道影响了哪些章节 | 改了商务Word，不知道有没有漏改技术Word |
| 多个项目同时进行时容易串 | 客户名、金额、参数、承诺串到别的项目 |
| 格式提取正确不等于内容事实正确 | AI按招标要求组织了输出，但内容可能是错的或过期的 |

**根本原因**：Word格式让AI处理不稳定，但知识库用纯文本格式，两者之间缺少稳定的转换机制。

## 打通方案：两层结构 + 投标Skill

### 架构

```
企业知识（纯文本）
    ↓ 投标Skill
标书输出（Word）
```

**两层结构**：

| 层次 | 内容 | 格式 | 作用 |
|---|---|---|---|
| 来源与交付层 | Word/PDF/Excel/图片/证明文件 | 原格式 | 保留原貌、法律证据、复杂版式、最终交付 |
| 语义知识层 | 企业资质、技术能力、业绩描述、标准响应 | 纯文本（Markdown） | 人和AI快速读取、准确检索、独立更新、追溯来源 |

**投标Skill职责**：

1. 从招标文件提取要求（章节、资格条件、评分项、格式）
2. 从知识库检索适用内容（带来源、状态、有效期）
3. 按招标要求组装标书
4. 转换成Word格式（保持格式要求）
5. 自动检查（漏项、冲突、失效材料、跨项目污染）
6. 标记需要人工确认的部分

### 分步实施

#### 第一步：稳定内容从Word模板拆到知识库

**识别稳定内容**：

- 企业资质（营业执照、资质证书、认证证书）
- 技术能力（核心技术、专利、研发团队）
- 业绩案例（合同、验收、客户证明）
- 标准响应（质保承诺、售后服务、培训方案）

**拆分规则**：

| 判断标准 | 说明 |
|---|---|
| 能否独立看懂 | 脱离Word文档，单独拿出来能读懂吗？有没有"如上""参考前文"？ |
| 能否独立更新和失效 | 这份内容会自己变化吗？失效时间独立吗？ |
| 是否跨项目复用 | 多个投标都会用到这份内容吗？ |

**整理到知识库**：

```
knowledge-base/
├── notes/
│   ├── 企业资质/
│   │   ├── 营业执照-有效期2027.md
│   │   └── ISO9001证书-有效期2026.md
│   ├── 技术能力/
│   │   ├── 核心技术说明.md
│   │   └── 研发团队介绍.md
│   ├── 业绩案例/
│   │   ├── 2025-某某项目-验收合格.md
│   │   └── 2024-某某项目-验收优秀.md
│   └── 标准响应/
│       ├── 质保承诺-标准版.md
│       └── 售后服务方案-标准版.md
└── sources/
    ├── 营业执照.pdf
    ├── ISO9001证书.pdf
    └── ...
```

**每个文件包含**：

```markdown
---
来源: 某某证书原件
日期: 2025-06-01
状态: 有效
有效期至: 2027-05-31
适用范围: 所有投标项目
---

## 企业资质

某某公司营业执照，统一社会信用代码：XXXXXXXXX

注册资本：1000万元
成立日期：2015年6月1日
经营范围：...

![营业执照](../sources/营业执照.pdf)
```

**保留在Word模板的内容**：

- 项目变量（客户名、项目名、金额、工期）
- 项目特定方案（根据招标要求定制的内容）
- 格式模板（表格样式、页眉页脚、封面）

#### 第二步：投标Skill初版

**Skill结构**：

```
tracks/bidding/
├── SKILL.md              # 入口：元数据 + 核心流程
├── references/
│   ├── 要求提取规则.md   # 怎么从招标文件提取要求
│   ├── 内容检索规则.md   # 怎么从知识库检索内容
│   ├── 格式转换规则.md   # 怎么转换成Word格式
│   └── 检查清单.md       # 自动检查项
└── scripts/
    ├── 提取招标要求.py   # 解析招标文件
    ├── 转换为Word.py     # Markdown转Word（保持格式）
    └── 检查标书.py       # 自动检查漏项、冲突
```

**SKILL.md核心流程**：

```markdown
---
name: bidding
description: >
  响应招标文件，从知识库提取内容，组装并检查标书。
  当用户要响应招标、生成标书、或提到"投标"时使用。
  不适用于知识库整理、文章写作等其他任务。
---

# 投标响应

## 核心流程

1. 提取招标要求 → 运行 `scripts/提取招标要求.py`，生成要求清单
2. 检索适用内容 → 按 `references/内容检索规则.md` 从知识库读取
3. 组装标书 → 按招标要求章节顺序组织内容
4. 转换格式 → 运行 `scripts/转换为Word.py`，保持招标要求的格式
5. 自动检查 → 运行 `scripts/检查标书.py`，对照 `references/检查清单.md`
6. 标记待确认 → 把需要人工确认的部分标黄

## 停止规则

遇到以下情况停下来问人：
- 招标要求清单无法提取完整
- 知识库缺少必需内容
- 两份知识内容矛盾
- 项目变量需要确认（客户名、金额、工期）
```

#### 第三步：测试与迭代

**选一份真实招标文件**：

1. 运行投标Skill，生成标书
2. 对照检查清单，记录问题：
   - 哪些内容没检索到？（知识库缺失）
   - 哪些内容检索错了？（检索规则问题）
   - 哪些格式转换错了？（转换脚本问题）
   - 哪些检查漏了？（检查清单不全）
3. 修正Skill，再跑一遍
4. 记录迭代：版本号 + 改了什么 + 为什么改

**迭代记录示例**：

| 版本 | 问题 | 改进 |
|---|---|---|
| 0.1.0 | 业绩案例检索不到 | 知识库缺"业绩案例"分类，补充整理 |
| 0.2.0 | 检索到的业绩案例是失效的 | 检索规则增加"状态:有效"过滤 |
| 0.3.0 | Word转换后表格格式错乱 | 转换脚本增加表格样式保持 |
| 0.4.0 | 没检查出跨项目污染 | 检查清单增加"客户名唯一性"检查 |

**项目变量.md**：

- 质保期2年

**投标Skill增加**：

- 检查"项目变量.md"存在且完整
- 检查"客户名"只出现在当前项目
- 检查"金额"只出现在当前项目
- 检查"业绩案例"符合项目特定要求

### 验收标准

**单份标书验收**：

| 验收项 | 检查方法 |
|---|---|
| 要求覆盖 | 招标文件要求均进入清单，能定位到标书响应位置 |
| 内容完整 | 应填写章节已生成，缺失信息有明确标记 |
| 事实可靠 | 企业事实、参数、案例、承诺可追溯到知识库来源 |
| 格式合规 | 章节、顺序、标题、表格、格式通过自动检查 |

**多项目隔离验收**：

| 验收项 | 检查方法 |
|---|---|
| 项目独立 | 标书A不包含项目B的客户名、金额、参数 |
| 内容复用 | 相同的企业资质、技术能力在两份标书中一致 |
| 更新同步 | 更新知识库中的一条内容，新标书自动使用新版本 |

## 关键收益

| 维度 | 当前（Word模板） | 打通后（知识库+Skill） |
|---|---|---|
| 单份制作时间 | 人工2天 | AI 1小时 + 人工确认0.5天 |
| 知识复用 | 每次重新判断 | 一次整理，多次复用 |
| 质量稳定性 | 依赖人工检查 | 自动检查 + 人工审核 |
| 多项目并行 | 容易串项目 | 项目隔离，自动检查 |
| 知识更新 | 改Word不知道影响范围 | 改知识库，新项目自动用新版 |
