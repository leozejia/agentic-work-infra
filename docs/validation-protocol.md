# 跨领域验证协议

## 目的

本协议规定怎样用真实项目验证 Agent 原生长期工作方法，同时让公共仓库保持抽象、公开和可复核。

验证不是证明一份文档写得自洽，而是检查：另一位 Agent 能否依据持久信息继续真实工作，使用正确真源，通过正式入口产出可接受结果，并让反馈改变下一次执行。

## 两层边界

### 公共方法仓

只保存：

- 候选问题、方法和可判定测试；
- 已脱敏且能独立支持结论的验证记录；
- 有效反例以及规则的晋升、收窄或删除决定；
- 垂直线路中仍然需要执行的专业规则。

### 本地真实项目

继续保存：

- 个人文章、图片、账号运营和平台状态；
- 客户资料、标书、企业知识和业务输入；
- 产品代码、运行状态、日志、测试数据和发布记录；
- 服务器、网络、密钥、机器路径和本地工具配置。

本地验证源的路径映射和未脱敏临时分析写入 `.local/`，该目录被 Git 忽略；真实项目和原始材料不复制进来。公共文档不得出现本机绝对路径、账号、客户主体、凭证、私有仓库信息或可以反推出真实业务材料的细节。

## 单次验证

每次验证只选择一个已经发生或能够真实执行的完整任务，并回答：

1. **意图**：用户真正要改变什么，什么结果才有价值？
2. **上下文**：任务实际使用了哪些有效事实、方法和历史决定？
3. **真源**：谁拥有当前有效事实，冲突和失效怎样处理？
4. **行动**：Agent 通过什么正式入口推进工作，哪些决定必须由人承担？
5. **结果**：什么用户可检查产物或现实变化证明任务完成？
6. **反馈**：失败、修改和使用结果怎样改变下一次执行？

先记录实际链路和失败，不为了匹配现有理论改写事实。

## 五项测试

- **续接测试**：新的会话或 Agent 不读取旧聊天，能否从正式入口恢复目标、边界和下一动作？
- **真源测试**：存在来源、正式产物、衍生物、旧版本或临时状态时，能否选择当前权威对象？
- **结果测试**：能否用真实入口和用户可检查结果判定完成，而不是依赖 Agent 声明或文件存在？
- **反馈测试**：真实失败或人工修改是否进入下一次工作，并能追溯它改变了什么？
- **迁移测试**：离开当前工具或线路后，候选约束是否仍成立；若不成立，差异是否明确留在垂直线路？

五项测试不是固定评分表。只运行当前判断实际依赖的测试，但必须公开未验证的部分。

## 规则去向

每次验证结束必须作出一种决定：

- **进入跨领域候选**：同一约束已经在至少两条独立线路的真实任务中得到支持，且尚无有效反例。
- **留在线路**：规则对当前专业工作有效，但依赖该线路独有目标、风险或载体。
- **继续观察**：证据不足以决定，保留问题和下一次能够区分假设的真实任务。
- **收窄或删除**：出现由规则本身导致、可复现且有记录的有效反例。

有限案例不能证明规则适用于所有行业。跨领域候选必须持续接受新线路反驳。

## 公开记录边界

公开验证记录只保留支持判断所需的最小事实：任务类型、触发条件、原规则、观察结果、反例或支持证据、规则去向。原始材料仍由本地项目拥有；公共记录不得复制完整文章、客户文档、代码仓库、截图、日志或平台数据。
