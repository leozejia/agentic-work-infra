# 跨线路核心候选

中文 | [English](README.en.md)

## 当前状态

这里不保存“适用于所有行业”的最终规范，只保存至少两条独立线路的真实任务共同支持、并且仍然接受反例的最小约束。

首批证据来自：

- [媒体生产：系列文章的正文与渠道衍生验证](../tracks/media-production/validations/article-derivation.md)
- [软件开发：单用途服务交付验证](../tracks/software-development/validations/single-purpose-service-delivery.md)

知识管理线路已经有领域候选方法，但尚未按共同协议形成独立验证记录，因此本轮不拿它为核心候选追加证明。

## 候选一：当前执行面必须可替换

一项长期工作的当前执行面只保存：

- 这次工作真正要改变什么；
- 已经接受的事实与决定；
- 当前边界和明确非目标；
- 下一项可执行动作；
- 应在什么结果或风险处停止并交还给人。

它服务跨会话、跨 Agent 的续接，不保存完整历史，也不替代产品事实、长期方法、原始内容或运行记录。完成或方向改变后，它应被新状态替换，而不是无限追加。

**支持证据**：媒体任务依靠当前主线、独立问题和停止点避免切错系列；开发任务依靠目标、现场边界、下一动作和回滚条件完成交接。

**可证伪条件**：如果一个真实长期任务在没有独立当前执行面的情况下仍能稳定续接，或维护它反而持续造成目标漂移与第二真源，应收窄本候选。

## 候选二：一个事实只能有一个权威所有者

长期工作通常同时存在原始事实、正式产物、衍生视图、当前执行面、临时过程和外部实时状态。它们可以互相引用，不能各自维护同一事实。

当发生冲突时，先按角色选择权威所有者：当前可观察的现实覆盖旧计划；正式真源覆盖衍生版本；已经确认的决定覆盖未确认推断。临时控制面不能反向改写正式内容。

**支持证据**：媒体任务把正文、渠道稿和平台状态分开；开发任务把方案、私有配置、Handoff 和现场运行状态分开，并在现场事实变化时修正执行路径。

**可证伪条件**：如果某类工作必须由多个对象共同拥有同一事实，且无法通过事务、事件或关系表达解决，应重新定义“事实”和“所有者”，不能强行去重。

## 候选三：完成必须回到正式入口和可检查结果

文件生成、状态更新、接口成功、进程退出、Agent 声明和界面提示都只能提供局部证据。工作完成至少需要：

1. 通过该工作真实使用的正式入口执行；
2. 产生目标用户或责任人能够检查、继续使用的结果；
3. 同时验证明确要求不得破坏的既有结果；
4. 把未验证、失败或等待状态诚实留在结论中；
5. 不可逆决定符合人的当次授权和领域责任边界。

**支持证据**：媒体任务要求完整正文、可用渠道资产和明确发布授权；开发任务同时验证新增公网结果与既有服务未受影响。

**可证伪条件**：如果某类工作没有外部入口或独立结果，例如纯探索和基础研究，应重新定义阶段性交付，不能用本候选强造一个虚假终态。

## 当前没有提升的内容

- 不建立统一对象分类、目录、字段、数据库或生命周期状态机；
- 不要求所有领域都使用同名 Handoff、正文或验收文件；
- 不把媒体人工发布门推广成所有开发动作的统一审批门；
- 不把开发调试工具和测试层级推广成媒体或知识管理规则；
- 不预设最终产物是 CMS、知识库、项目管理软件、Skill 或可视化面板。

领域独有的目标、风险和载体继续由各条线路拥有。新的线路首先尝试反驳这三条候选，而不是套用它们证明自己正确。
